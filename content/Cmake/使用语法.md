# 使用语法

## add_library

```cmake
add_library(xxxx 类型)
```

CMake 中常见的库类型：

| 类型        | 含义   | 用途                                 |
| ----------- | ------ | ------------------------------------ |
| `STATIC`    | 静态库 | 编译生成 `.lib` / `.a`；静态库文件   |
| `SHARED`    | 动态库 | 编译生成 `.dll` / `.so`              |
| `MODULE`    | 模块库 | 通常用于插件,编译生成 `.dll` / `.so` |
| `INTERFACE` | 接口库 | 传递依赖配置，不生成实际库文件       |

### STATIC

比如颜色计算模块 `color_math`。程序构建时把它链接进去，交付程序时通常不用再带上 `color_math` 库文件。**修改库代码后，使用它的程序需要重新链接。**

```c++
add_library(color_math STATIC color_math.cpp)

add_executable(photo_viewer main.cpp)
target_link_libraries(photo_viewer PRIVATE color_math)
```

### SHARED

比如查看器和图片批处理工具都要用的 `image_core`。它单独生成 `.dll` 或 `.so`，程序运行时需要能找到它。Windows 上通常还会生成一个供链接使用的导入库 `.lib`

```c++
add_library(image_core SHARED image_core.cpp)

add_executable(photo_viewer main.cpp)
target_link_libraries(photo_viewer PRIVATE image_core)
```

### MODULE

比如一个可选的 HEIF 图片格式插件。查看器运行后发现插件，再通过 `LoadLibrary` 或 `dlopen` 加载它。它通常不会像普通库那样写进 `target_link_libraries()`，而是由程序按插件接口加载。

```c++
add_library(heif_plugin MODULE heif_plugin.cpp)
```

### INTERFACE

比如一个只有头文件的工具库。`INTERFACE` target 可以告诉使用者头文件在哪里、需要什么 C++ 标准或编译宏；它自己不编译成 `.lib`、`.a`、`.dll` 或 `.so`。

```c++
add_library(image_headers INTERFACE)

target_include_directories(image_headers
    INTERFACE ${CMAKE_CURRENT_SOURCE_DIR}/include
)
target_compile_features(image_headers INTERFACE cxx_std_20)

target_link_libraries(photo_viewer PRIVATE image_headers)
```

### STATIC、SHARED和MODULE的区别

> [!NOTE]
>
> **静态库**：先单独编译成 `.a` / `.lib`。构建程序时，再把需要的库代码合进最终的可执行文件。修改静态库后，使用它的程序要重新链接。
>
> **动态库**：先单独编译成 `.so` / `.dll`。程序链接时记录对它的依赖，运行时再加载这个库文件。
>
> **插件库**：先单独编译成 `.so` / `.dll`，主要用作插件。宿主程序运行时找到并加载它，常见方式包括 `LoadLibrary`、`dlopen` 或插件框架；**不可以作为`target_link_libraries`连接进去**。
>
> ```
> 静态库：源代码 → .a/.lib → 链接时合进程序(需要重新--build，重新和其他源代码连接，
> 但是不需要编译其他没没有改版的源代码)
> 动态库：源代码 → .so/.dll → 程序运行时加载（直接运行）
> ```

## target_link_libraries

```c++
target_include_directories(
  xxxxx
  INTERFACE
    "${xx}/include/xxxx"
    "${xx}/include/xxx"
    "${xx}/lib/glib-2.0/include"
)
```

**使用 `xxxxx` 的 target 会获得这些 include 路径**。编译器因此能找到 `#include` 所需的头文件

> [!NOTE]
>
> 告诉编译器去哪里找 `#include` 的头文件。

## find_library

在指定目录里查找 `.lib`、`.a` 或 `.so` 等库文件。

```cmake
find_library(
    `保存查找结果的变量名`
    `要找的库名`
    PATHS "${TACTICLENS_GSTREAMER_ROOT}/lib" # PATHS->指定搜索目录
    NO_DEFAULT_PATH # 只在指定的目录中找，不再搜索系统默认目录等其他位置
    REQUIRED # 如果找不到这个库，就报错并停止 CMake 配置。
  )
```
