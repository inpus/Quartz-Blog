#### 获取extradata（在初始化视频编码之后）

```c++
extradata_size = h264_encoder_->GetSequenceParams(extradata, sizeof(extradata));
```

###### **封装格式说明**

- **Annex-B（带起始码）**：
  - **结构**：[0x000001 或 0x00000001] + [NALU 数据]
  - **SPS/PPS**：作为普通的 NALU 夹杂在视频数据帧中间（**In-band 内联传输**）。
- **AVCC（带长度前缀，也叫 AVC1）**：
  - **结构**：[4字节长度信息] + [NALU 数据]
  - **SPS/PPS**：不放在数据帧中，而是单独存放在文件头或外挂参数中（**Out-of-band 带外传输**，如 MP4 的 avcC Box、FFmpeg 的 extradata）。

###### 通过extradata提取sps和pps

- h264编码输出的封装格式为aneex-b

> 通过获取的annex-b，判断nalu_type=7,8来cpy出对应sps和pps数据

###### 封装视频头（**AVC Sequence Header**）

- 标签头（5字节）

| 1    | 0x17             | 高 4 位 1 = Keyframe（关键帧）；<br>低 4 位 7 = AVC（H.264 编码）。 |
| ---- | ---------------- | ------------------------------------------------------------ |
| 2    | 0x00             | **AVCPacketType**：0x00 表示当前包是 **AVC Sequence Header**（若为 0x01 则表示具体的 NALU 视频帧）。 |
| 3~5  | 0x00, 0x00, 0x00 | **Composition Time (CTS 偏移)**：3 字节，Sequence Header 该字段恒为 0。 |

- AVCDecoderConfigurationRecord（avcc核心配置）

| 字节   | 数据     | 含义与解析                                                   |
| ------ | -------- | ------------------------------------------------------------ |
| 6      | 0x01     | **configurationVersion**：版本号，固定为 1。                 |
| 7      | sps[1]   | **AVCProfileIndication**：编码 Profile（如 Baseline=66, Main=77, High=100）。 |
| 8      | sps[2]   | **profile_compatibility**：Profile 兼容性标志。              |
| 9      | sps[3]   | **AVCLevelIndication**：编码 Level（如 Level 3.1、4.1 等）。 |
| 10     | 0xFF     | **lengthSizeMinusOne**：<br>高 6 位为保留位全 1 (111111)；<br>低 2 位表示后续 NALU 长度占几个字节（11 二进制为 3，代表 `3+1=43+1=4` 字节长度）。<br>11111111 即 0xFF。 |
| 11     | 0xE1     | **numOfSequenceParameterSets (SPS 个数)**：<br>高 3 位保留全 1 (111)；<br>低 5 位是 SPS 数量（00001 表示有 1 个 SPS）。<br>11100001 即 0xE1。 |
| 12~13  | 2 字节   | **SPS 长度**（大端字节序，高位在前，低位在后）。             |
| 变长   | sps_size | **SPS 的具体内容**（不带 00 00 00 01 起始码）。              |
| 1 字节 | 0x01     | **numOfPictureParameterSets (PPS 个数)**：固定 1 个字节，值等于 1。 |
| 2 字节 | 2 字节   | **PPS 长度**（大端字节序）。                                 |
| 变长   | pps_size | **PPS 的具体内容**（不带 00 00 00 01 起始码）。              |

#### 发送

根据nalu type来判断是否为关键帧，如果是第一个关键帧，则先发包头，再发数据

- nalu type是在编码数据中的第一个字节

| NALU Type 值 | 英文全称                                 | 中文含义                   | 对应 RTMP 行为                                         |
| ------------ | ---------------------------------------- | -------------------------- | ------------------------------------------------------ |
| **7**        | **SPS** (Sequence Parameter Set)         | 序列参数集                 | 打包进 **AVC Sequence Header** (包头，发一次)          |
| **8**        | **PPS** (Picture Parameter Set)          | 图像参数集                 | 打包进 **AVC Sequence Header** (包头，发一次)          |
| **5**        | **IDR** (Instantaneous Decoding Refresh) | **关键帧 (I 帧)**          | 作为**关键视频帧**发送 (RTMP 标签头填 **0x17 0x01**)   |
| **1**        | **Non-IDR Slice**                        | **非关键帧 (P 帧 / B 帧)** | 作为**非关键视频帧**发送 (RTMP 标签头填 **0x27 0x01**) |

### 接受信令服务器命令

> 1. 根据对应相应命令进行推流，先是join创建房间，setcode
> 2. 然后等待拉流端申请流，服务器会发送创建流命令，然后通过推流端创建流，然后发送到rtmp服务器中，然后服务器回复play_stream进行回调捕获编码，发送数据到rtmp服务器中
> 3. 将收到创建流信息，发送到所有拉流端上，告诉所有拉流端url，进行发送playstream，获取数据

##### 找到对应流信息

```c++
pFormateCtx_->streams[i]->codecpar->codec_type == AVMEDIA_TYPE_VIDEO
//更新视频流索引
videoIndex = i;
//时长
avContext_->videoDuration = pFormateCtx_->streams[i]->duration * av_q2d(pFormateCtx_->streams[i]->time_base);
```

> 更新视频流索引和时长
>
> `av_q2d`：把 FFmpeg 分数结构体 `AVRational` 转成 double 浮点数
>
> 1. `streams[i]->duration`：**整数，单位是 time_base 刻度**，不是秒。
>
> 2. `streams[i]->time_base`AVRational，流的时间基。
>
>    例如 
>
>    `time_base={1,1000}`： → 1/1000 秒，一个刻度 = 1 毫秒。
>
> > `duration * time_base` = 真实秒数。
> >
> > 因为 不能直接乘结构体，所以用 `av_q2d()` 把分数变成浮点数再相乘。
