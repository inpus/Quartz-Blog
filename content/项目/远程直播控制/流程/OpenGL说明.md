## OpenGL说明

### initializeGL

#### 什么是 VAO / VBO / EBO？（做一块“屏幕画布”）

- **VBO（顶点缓存）**：**画板的4个角**。告诉显卡，屏幕的4个角在什么三维坐标（[-1, 1] 范围），以及画面的4个角对应贴图的哪个位置。
- **EBO（索引缓存）**：**拼装说明书**。OpenGL 只能画三角形，所以用 2 个三角形拼成 1 个矩形（顶点 0-1-3 和 1-2-3）。
- **VAO（顶点数组对象）**：**图纸夹**。把上面的顶点格式配置全部打包记下来，以后只要激活 VAO，显卡就知道怎么画这个矩形了

#### 什么是着色器 Shader？（显卡上的小程序）

- **顶点着色器（Vertex Shader）**：负责**定位置**。确保视频矩形准确贴在窗口指定位置。

- **片段着色器（Fragment Shader）**：负责**调颜色**。读取 YUV 数据，套用转换公式（

  ```
  R=Y+1.402×V…R=Y+1.402×V…
  ```

  ），计算出屏幕上每个像素最终的 RGB 颜色。

  

### Repaint & repaintTexYUV420P

当解码器解出一帧 AVFrame 视频数据时触发：

#### 1. 为什么创建 3 个纹理（Texture）？

因为格式是 **YUV420P（Planar 平面格式）**，数据是分开存的：

- **Y（亮度/黑白画面）**：分辨率是原尺寸 width × height。
- **U（蓝色色度）**：分辨率减半 width/2 × height/2。
- **V（红色色度）**：分辨率减半 width/2 × height/2。

> **做法**：在显存里开辟 3 块小空间（纹理），把 frame->data[0]、data[1]、data[2] 分别传上去。

#### 代码里为什么要注意 linesize？

- 显存和内存对齐可能会导致一行数据的字节数比视频实际宽度多一点（有空隙填充）。
- setRowLength(frame->linesize[x]) 就是告诉显卡：“读完一行后跳过填充字节，按实际行宽读下一行”，防止画面花屏/斜切。

### resizeGL & paintGL

数据送上去了，Qt 会自动调用 paintGL() 执行真正的绘制：

```
1. glClear()            -> 把上一帧擦掉，背景涂黑
2. glViewport()         -> 居中自适应缩放（防止拉伸变形，两边留黑边）
3. 绑定着色器           -> 启动 YUV -> RGB 调色公式
4. 绑定 3 个纹理        -> 把 Y/U/V 传给着色器对应通道
5. 绑定 VAO 并 Draw     -> 显卡瞬间并发计算几百万个像素的 RGB，贴满矩形
6. 解绑                 -> 恢复初始状态，准备下一次绘制
```

#### 概括流程

```text
4个顶点
   ↓
2个三角形
   ↓
UV告诉GPU图片怎么覆盖
   ↓
GPU自动插值每个Fragment的UV
   ↓
从同一张Texture取颜色
   ↓
屏幕上得到完整图片
```
