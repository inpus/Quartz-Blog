## 视频采集

#### WGC捕获数据结构体

```c++
struct WGCscreenCapture::Impl
{
    // D3D11 设备与上下文，Direct3D11 渲染管线
    ComPtr<ID3D11Device> d3dDevice;
    ComPtr<ID3D11DeviceContext> d3dContext;
    
    // Windows Runtime 封装的Direct3D设备桥接（WinRT ↔ D3D11）
    IDirect3DDevice direct3DDevice{nullptr};
    
    // 捕获目标：代表一个窗口 / 一块显示器
    GraphicsCaptureItem item{nullptr};
    
    // 帧池：存放捕获到的画面帧纹理，循环复用GPU资源
    Direct3D11CaptureFramePool framePool{nullptr};
    
    // 捕获会话：启动、停止捕获的控制器
    GraphicsCaptureSession session{nullptr};
    
    // 捕获区域：裁剪矩形（左、上、宽、高）
    CaptureRect captureRegion;
    
    // 初始化标记，防止重复初始化/重复销毁
    bool initialized = false;
};
```

> `GraphicsCaptureItem`：**你要抓谁**（窗口 / 显示器）
>
> `Direct3D11CaptureFramePool`：**画面缓冲区队列**，持续产出帧
>
> `GraphicsCaptureSession`：**捕获开关**，控制开始 / 暂停捕获
>
> `IDirect3DDevice`：桥接传统 D3D11 和 WinRT GraphicsCapture API
>
> `d3dDevice/d3dContext`：你自己的 D3D 上下文，用来拷贝纹理、读写画面

- WGC只能采集一个显示器

#### 初始化COM

```c++
HRESULT hr = CoInitializeEx(nullptr, COINIT_MULTITHREADED);
```

> COM 不是系统天生自动就绪的运行环境，每个想要使用 COM 对象的线程，必须主动告知系统：“我这条线程要使用 COM，采用哪种线程模型（STA/MTA）”，这个告知动作就是 `CoInitializeEx`

> ###### STA（COINIT_APARTMENTTHREADED）
>
> 每个 STA 线程独立单元。
>
> COM 对象默认**只能在创建它的线程直接调用**；
>
> 别的线程想要访问，系统自动生成代理 / 存根，通过线程消息队列转发调用。
>
> 👉 UI 主线程标准方案，不适合后台录屏捕获线程。
>
> ###### MTA（COINIT_MULTITHREADED，你正在用的）
>
> 进程内所有 MTA 线程共享同一个单元。
>
> 要求 COM 对象本身支持多线程安全调用；
>
> 对象指针可以在线程之间直接传递，**不需要代理中转**。
>
> ✅ D3D、WGC 后台捕获线程首选。

#### 生成d3d设备，上下文，转换winrt d3d设备

##### 创建D3D11 设备对象

```c++
hr = D3D11CreateDevice(
    nullptr,                          // pAdapter: nullptr = 默认显卡
    D3D_DRIVER_TYPE_HARDWARE,         // 使用硬件GPU渲染
    nullptr,                          // 软件驱动句柄，硬件模式忽略
    deviceFlags,                      // 创建标志
    featureLevels,                    // 期望支持的特性等级列表（从高到低尝试）
    ARRAYSIZE(featureLevels),         // 数组数量
    D3D11_SDK_VERSION,                // SDK版本固定填这个
    &d3dDevice,                       // [输出]D3D11设备
    nullptr,                          // [输出]协商成功的FeatureLevel，这里不需要接收
    &d3dContext);                     // [输出]立即上下文 ImmediateContext
```

> `deviceFlags`：选择支持的数据格式`D3D11_CREATE_DEVICE_BGRA_SUPPORT`（支持BGRA）

> **`&d3dDevice` → ppDevice**
>
> 输出：创建成功的 **ID3D11Device 对象**，D3D 主设备。
>
> **`nullptr` → pFeatureLevel（你传了 nullptr）**
>
> 作用：输出**本次协商成功的特性等级**。
>
> 如果你改成传变量：
>
> **`&d3dContext` → ppImmediateContext**
>
> 输出：**立即渲染上下文（Immediate Context）**，用来发起所有 GPU 命令（CopyResource、Draw、Clear 等）。

##### D3D11转成DX

```c++
ComPtr<IDXGIDevice> dxgiDevice;
hr = d3dDevice.As(&dxgiDevice);
```

> `d3dDevice`：是D3D11的设备对象

> `ComPtr<T>::As()` 等价于 COM 的 `QueryInterface`：
>
> > 查询当前对象，是否支持目标接口 `IDXGIDevice`；成功则拿到接口智能指针。
> >
> > **多了一个接口指针引用，没有创建新对象，COM 引用计数会 + 1，**
> >
> > 类比：
> >
> > 同一个人（底层 D3D 设备 COM 对象）：
> >
> > - `ID3D11Device` 证件：负责画画、渲染、纹理；
> >
> > - `IDXGIDevice `另一张证件：负责对接显卡硬件、显示器、DXGI 捕获、交换链。
> >
> >   你只是向这个人索要第二张证件，人本身没变。

> `ID3D11Device` 是 D3D 渲染层；`IDXGIDevice` 是上层图形适配器、显示输出、设备共享层。
>
> 获取当前显卡适配器 `IDXGIAdapter`（拿到显卡名称、显存）；实现纹理跨进程共享
>
> **最重要：配合 `CreateDirect3D11DeviceFromDXGIDevice`，生成 WinRT 所需的 `IDirect3DDevice`**
>
> - **没有独立创建 IDXGIDevice 的公开函数，所以只能这样方法转接**
>
> > ID3D11Device（D3D渲染设备）        
> >
> > ​			↓
> >
> >  实现了 IDXGIDevice（DXGI基础设施接口）

##### 获取inspectableDevice设备

```c++
ComPtr<IInspectable> inspectableDevice;
hr = CreateDirect3D11DeviceFromDXGIDevice(
    dxgiDevice.Get(),                // 入参：IDXGIDevice*（来自ID3D11Device查询）
    inspectableDevice.GetAddressOf() // 出参：IInspectable**，承载 IDirect3DDevice
);
```

> `dxgiDevice.Get()`：取出 `ComPtr<IDXGIDevice>` 的原始裸指针；
>
> `GetAddressOf()`：返回 `IInspectable**`，ComPtr 标准传参写法（等价 `&rawPointer`）。

> 输出的 `IInspectable*`**作为父接口** 可以**强转成 `IDirect3DDevice`**
>
> ```c++
> // 你Impl里面的成员：IDirect3DDevice direct3DDevice{nullptr};
> *reinterpret_cast<IInspectable**>(&impl->direct3DDevice) = inspectableDevice.Detach();
> ```

- **作用**： 把 **原生 COM 的 IDXGIDevice（经典 D3D11 C++ API）** 包装成 **Windows Runtime（WinRT）类型 IDirect3DDevice**。而 `IDirect3DDevice` 继承自 `IInspectable`，所以先用 `IInspectable` 接收。

##### inspectableDevice设备转成 D3D设备对象

```c++
IDirect3DDevice direct3DDevice{
inspectableDevice.Detach(), //交出裸指针，WRL 放弃管理权，引用计数不变
take_ownership_from_abi // 指针已经带 AddRef，只接管，不额外 AddRef
};
```

> `winrt::take_ownership_from_abi`告诉 com_ptr：
>
> > “这个传入的裸指针已经有合法 AddRef 计数，你直接接管生命周期，后续由 `direct3DDevice` 对象负责在析构时调用 `Release()`

##### 总结

> CreateDirect3D11DeviceFromDXGIDevice → 新建包装COM对象 + AddRef(计数=1) → 存入 inspectableDevice（ComPtr持有，计数依旧1） 
>
> → inspectableDevice.Detach()   ✅ 返回裸指针   ✅ ComPtr不再持有   ✅ COM对象引用计数仍然 = 1 
>
> → 传入 **winrt::IDirect3DDevice **构造 + take_ownership_from_abi   
>
> ✅ WinRT对象直接接管这份引用   
>
> ✅ 不AddRef 
>
> → 当 direct3DDevice 生命周期结束析构时 → 自动Release()，计数归零，对象销毁

#### 创建帧池和采集会话

```c++
Direct3D11CaptureFramePool framePool{nullptr};
GraphicsCaptureSession session{nullptr};
try
{
    framePool = Direct3D11CaptureFramePool::CreateFreeThreaded(
        direct3DDevice,                                  // WinRT D3D设备
        DirectXPixelFormat::B8G8R8A8UIntNormalized,     // 像素格式 BGRA
        2,                                               // 缓冲区数量
        item.Size());                                    // 捕获分辨率

    session = framePool.CreateCaptureSession(item);
}
catch (const hresult_error&)
{
    return false;
}
```

> `Direct3D11CaptureFramePool `：
>
> WGC**不会持续生成新纹理**，而是预先分配一组 GPU 纹理缓冲区，循环复用，这组缓冲区就是帧池。
>
> - 捕获产生的每一帧 `Direct3D11CaptureFrame` 都来自池内资源；
> - 帧用完必须调用 `frame.Close()` 归还，否则池耗尽、停止推送帧；
> - 帧池**绑定唯一**：`IDirect3DDevice` + 像素格式 + 分辨率。

> `CreateFreeThreaded： `后台捕获

> `GraphicsCaptureSession`：捕获会话控制器；
>
> 把「捕获目标」和「帧池」绑定，创建捕获会话；
>
> session.StartCapture();捕获才正式启动。

> > 获取一个 COM 接口、类或者类型对应的 GUID（UUID）。

#### 准备一个 CPU 端的帧缓冲区

```c++
    const size_t stride = static_cast<size_t>(outWidth) * 4u;
    const size_t requiredSize = stride * static_cast<size_t>(outHeight);

    if (!impl_->frameBuffer || impl_->frameBuffer->size() < requiredSize)
    {
        impl_->frameBuffer = std::make_shared<std::vector<uint8_t>>(requiredSize);
    }
    std::shared_ptr<std::vector<uint8_t>> frameBuffer = impl_->frameBuffer;
    frameBuffer->resize(requiredSize);
```

> `const size_t stride = static_cast<size_t>(outWidth) * 4u;`
>
> 计算一行字节数,RGBA一共4个字节
>
> `requiredSize `：是整帧的大小

> 根据帧大小判断是否有足够的缓冲区大小

#### 把GPU的捕获纹理设置cpu可访问的纹理

```c++
D3D11_TEXTURE2D_DESC stagingDesc = desc;
stagingDesc.Usage = D3D11_USAGE_STAGING;
stagingDesc.BindFlags = 0;
stagingDesc.CPUAccessFlags = D3D11_CPU_ACCESS_READ;
stagingDesc.MiscFlags = 0;
ComPtr<ID3D11Texture2D> stagingTexture;
HRESULT hr = impl_->d3dDevice->CreateTexture2D(&stagingDesc, nullptr, &stagingTexture);
impl_->d3dContext->CopyResource(stagingTexture.Get(), texture.Get());
```

> `stagingDesc`：创建CPU 可读的 staging texture（暂存纹理）
>
> `D3D11_USAGE_STAGING`：CPU访问；决定这个资源是什么类型（暂存类型，不用于渲染）、用途是什么（用于 GPU ↔ CPU 数据交换）
>
> `BindFlags = 0` ：去掉GPU绑定
>
> `D3D11_CPU_ACCESS_READ`：开启CPU读取权限；决定 CPU 能不能读这个资源

> `CreateTexture2D`：创建纹理，此时还没有数据
>
> `CopyResource`：才有数据复制，但是还是GPU-GPU之间

#### 将GPU暂存纹理复制到CPU内存buffer中

```c++
D3D11_MAPPED_SUBRESOURCE mapped{};
hr = impl_->d3dContext->Map(stagingTexture.Get(), 0, D3D11_MAP_READ, 0, &mapped);
    const uint8_t* srcPixels = static_cast<const uint8_t*>(mapped.pData);
    for (int32_t y = 0; y < outHeight; ++y)
    {
        const size_t srcOffset =
            static_cast<size_t>(sourceTop + y) * mapped.RowPitch +
            static_cast<size_t>(sourceLeft) * 4u;
        std::memcpy(
            frameBuffer->data() + static_cast<size_t>(y) * stride,
            srcPixels + srcOffset,
            stride);
    }
    impl_->d3dContext->Unmap(stagingTexture.Get(), 0);
```

> `D3D11_MAPPED_SUBRESOURCE mapped{};`：Map 获取 CPU 可访问地址
>
> `impl_->d3dContext->Map`：把 GPU 的 staging texture 映射到 CPU 地址空间
>
> `mapped.pData`：就是CPU客房的像素首地址
>
> `uint8_t* srcPixels`经过for循环按行复制

> `impl_->d3dContext->Unmap`告诉Direct3D，CPU访问结束；
>
> 如果不unmap:
>
> - 资源仍然处于 CPU 访问状态
>
> - GPU 可能无法继续使用它
>
> - 后续 Map 可能失败
>
> - 可能产生同步问题

##### 创建一个视频帧描述

```c++
struct VideoFrame
{
    PixelFormat format = PixelFormat::BGRA8;
    uint32_t width = 0;
    uint32_t height = 0;
    int32_t linesize[4] = {0, 0, 0, 0}; // 类似 AVFrame->linesize，一行占多少字节

```

> linesize[0]只设置这个因为bgra是一个平面，如果是yuv就是三个平面了(gpu不用加平面格式)
