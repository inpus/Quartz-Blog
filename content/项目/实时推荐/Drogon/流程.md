# Drogon 服务端流程

> 本文按运行路径说明 Drogon 在 TacticLens 中的位置。源码实现细节见 [实现.md](实现.md)。服务端源码位于仓库 <code>server/</code>；Linux 服务端工作树可能有未提交变更，本文按当前可见源码描述，不据此判断线上进程状态。

**两条网络路径要分开看：**

- WebSocket <code>/ws</code> 承载会话控制和 WebRTC 信令，例如 <code>start</code>、<code>webrtc_offer</code>、<code>webrtc_ice</code>、<code>stop</code>。
- 音视频媒体经 WebRTC 的 RTP/SRTP 通道到达服务端，不封装成 WebSocket 媒体消息。当前 <code>WsHandler</code> 对二进制协议只接受 Control 类型，其它类型会拒绝。

## WebSocket 会话与 WebRTC 建链

浏览器端先加载面板；默认情况下，JavaScript 会先通过一次 <code>GET /api/runtime</code> 读取 WebSocket 端口，再执行 <code>new WebSocket(...)</code>。这会发起一次 **WebSocket opening handshake（Upgrade 握手）**，不是视频请求。

### Upgrade 握手实际做什么

浏览器用 HTTP/1.1 GET 请求询问服务器是否接受切换协议。请求中的 <code>Connection: Upgrade</code> 和 <code>Upgrade: websocket</code> 表示要从 HTTP 切换到 WebSocket；<code>Sec-WebSocket-Version</code> 和 <code>Sec-WebSocket-Key</code> 用于完成 WebSocket 协议握手。浏览器会自动生成这些字段，业务 JavaScript 不需要手工拼装。

示意请求与响应如下：

~~~http
GET /ws/panel?token=... HTTP/1.1
Connection: Upgrade
Upgrade: websocket
Sec-WebSocket-Version: 13
Sec-WebSocket-Key: <browser-generated-value>
~~~

~~~http
HTTP/1.1 101 Switching Protocols
Connection: Upgrade
Upgrade: websocket
Sec-WebSocket-Accept: <server-calculated-value>
~~~

收到 <code>101 Switching Protocols</code> 后，**同一条 TCP 连接**切换为双向 WebSocket 连接。后续应用消息以 WebSocket frame 传输，不再是一条条 HTTP GET/响应。<code>Sec-WebSocket-Key/Accept</code> 是协议握手校验，不是用户身份认证。

在本项目中，浏览器把 <code>token</code> 放在 WebSocket URL 查询参数里。Drogon 完成 Upgrade 并返回响应后，才调用 <code>WsHandler::handleNewConnection()</code>；该回调校验 token，失败时调用 <code>forceClose()</code>，通过后再区分 <code>/ws</code> 采集会话和 <code>/ws/panel</code> 面板连接。因此，收到 101 只表示 WebSocket 协议握手已完成，应用 token 校验仍需通过。握手规范见 [RFC 6455 §4](https://www.rfc-editor.org/rfc/rfc6455.html#section-4)；[Drogon WebSocketController 文档](https://github.com/drogonframework/drogon/wiki/ENG-04-3-Controller-WebSocketController) 说明 <code>handleNewConnection()</code> 在连接建立、框架返回响应后调用。

### 采集端 <code>/ws</code> 会话与 WebRTC 建链

Upgrade 成功、token 通过后，采集端在这条长连接上发送 control 消息。Offer、ICE、ping 和 stop 都是同一 WebSocket 连接上的后续消息；WebRTC 建成后，音视频媒体另走 RTP/SRTP 通道。

~~~mermaid
sequenceDiagram
    participant C as Windows 客户端
    participant D as Drogon / WsHandler
    participant S as SessionManager
    participant Q as MediaService 命令队列
    participant M as MediaService / WebRtcReceiver
    participant W as WebRTC 媒体通道
    participant I as IngestPipeline / EventBus

    C->>D: HTTP GET /ws?token=... + Upgrade 请求头
    D-->>C: HTTP 101 Switching Protocols
    Note over C,D: 同一 TCP 连接切换为双向 WebSocket；后续收发 frame，不重复发 HTTP GET
    D->>D: handleNewConnection() 校验 token

    alt token 缺失或错误
        D->>C: forceClose()
    else token 通过
        D->>S: 创建 Session
        C->>D: WebSocket Control frame：start
        D->>D: onControl() 校验并进入 handleControl()
        D->>S: 注册唯一 session_id
        D->>Q: startMedia() 投递 attach
        D-->>C: started + media_epoch

        loop WebRTC Offer / Answer / ICE 信令
            C->>D: WebSocket frame：webrtc_offer / webrtc_ice
            D->>D: 校验 session_id 与 media_epoch
            D->>Q: mediaControl() 入队
            Q->>M: 处理 offer / ICE
            M-->>D: answer / ICE 回调
            D-->>C: WebSocket frame：answer / ICE
        end

        C->>W: ICE / DTLS 建立后发送 RTP / SRTP
        W->>M: 解码视频与两路音频
        M->>I: 视频分发；音频组块并发布到 EventBus

        loop WebSocket 会话持续期间
            C->>D: WebSocket frame：ping / clock_offset
            D-->>C: WebSocket frame：pong / media_status
        end

        C->>D: WebSocket frame：stop + 最终媒体端点
        D->>Q: 投递 stop
        Q->>M: 排空媒体、关闭 PeerConnection、写报告
        M-->>C: WebSocket frame：stopped / media_status
    end
~~~

### 面板 <code>/ws/panel</code> 长连接与消息循环

面板连接建立后，服务端可以随观测和推荐结果到达而推送消息；面板也可在同一连接上发 ping、hello 和延迟采样。WebSocket 连接断开时，Drogon 调用关闭回调并从下行连接表移除。

~~~mermaid
sequenceDiagram
    participant B as 浏览器面板
    participant D as Drogon
    participant H as WsHandler
    participant L as WsDownlink

    B->>D: GET /api/runtime（默认读取 WS 端口）
    D-->>B: JSON：websocket_port
    B->>D: HTTP GET /ws/panel?token=... + Upgrade 请求头
    D-->>B: HTTP 101 Switching Protocols
    Note over B,D: 同一 TCP 连接成为 WebSocket 长连接
    D->>H: handleNewConnection()
    H->>H: 校验 query token

    alt token 缺失或错误
        H->>D: forceClose()
    else token 通过
        H->>L: registerConn()
        loop 连接保持期间
            L-->>B: WebSocket frame：ocr_observation / vlm_event / recommendation
            B->>H: WebSocket frame：ping / hello / latency_sample
            H-->>B: WebSocket frame：pong（收到 ping 时）
        end
        B->>D: WebSocket Close frame 或 TCP 连接断开
        D->>H: handleConnectionClosed()
        H->>L: unregisterConn()
    end
~~~

面板收到观测 frame 后由 <code>onmessage</code> 分发给对应处理器。<code>live.tick()</code> 每 400 ms 检查本地保存的观测和查询条件；这个定时器本身不发 GET。位置与条件可用且需要更新推荐时，面板才 <code>POST /api/clips/query</code>；收到新片段 URL 后设置 <code>video.src</code>，浏览器才 <code>GET /clips/{file}</code>。连接和推荐代码见 <code>panel/connection.js#L8-L17</code>、<code>panel/panel.js#L48-L82</code>、<code>panel/panel-live.js#L104-L157</code>。

### 建链检查点

| 阶段 | 能确认什么 | 还不能确认什么 |
|---|---|---|
| WebSocket 握手与 token 校验 | 控制连接通过鉴权 | WebRTC 尚未协商 |
| 收到 <code>started</code> | 服务端接受协议 v2、WebRTC 会话并分配 <code>media_epoch</code> | ICE/DTLS 尚未连通 |
| Offer/Answer 与 ICE 交换 | 信令已送达双方 | 媒体未必已到达 |
| WebRTC 通道连通 | PeerConnection 建链 | 下游一定已处理完媒体 |
| MediaService 收到帧/音频 | 服务端媒体接收回调有数据 | 仍需检查队列、存档和推理结果 |

## 媒体到业务处理的分流

MediaService 在线程中轮询 WebRTC 接收端。解码后的视频进入有界队列，再通过 <code>IngestPipeline</code> 分发给已注册帧 tap；CS2 与 Oopz 音频分别组块，发布到 EventBus，并按配置写入音频存档。

    C --> D["MediaService drain"]

面板输出有多个来源：FastLane 的推荐结果、Perception/VLM 的观察消息、MediaService 状态等都可经 <code>WsDownlink</code> 广播给 <code>/ws/panel</code>。<code>/ws/panel</code> 是独立的面板连接，不会被登记为采集 Session。

## Drogon 请求如何分发到项目 Handler

Drogon listener 接入连接后，底层 Trantor 的 I/O 事件循环处理 socket 读写。Drogon 再按 HTTP 方法和路径路由普通请求；WebSocket 请求先完成 Upgrade，再按 WebSocketController 路径建立连接并调用连接回调。

~~~mermaid
flowchart TD
    A["客户端 / 浏览器请求"] --> B["Drogon Listener"]
    B --> C["Trantor I/O EventLoop<br/>Linux 底层使用 epoll"]
    C --> D{"WebSocket Upgrade?"}

    D -->|"否：HTTP 请求"| E{"匹配 HTTP 方法与路径"}
    E -->|"GET /api/runtime"| R["server_main.cpp 注册回调<br/>返回运行状态 JSON"]
    E -->|"POST /api/clips/query"| Q["server_main.cpp 注册回调<br/>Bearer 校验 → SQLite 查询"]
    E -->|"GET /clips/{file}"| Clip["Clips::get()<br/>HTTP Range 处理"]
    E -->|"/internal/agent/*"| Agent["AgentBridge::routes()<br/>本地来源与 token 校验"]
    E -->|"面板静态路径"| Static["Drogon document root<br/>cfg.panel_dir"]
    E -->|"没有匹配路由"| NotFound["Drogon 404"]

    D -->|"是：Upgrade 请求"| Upgrade["按 WebSocket 路径交给 Drogon"]
    Upgrade --> Response101["握手接受时返回 HTTP 101"]
    Response101 --> SameConn["同一 TCP 连接切换为 WebSocket<br/>后续传输 WebSocket frame"]
    SameConn --> NewConn["handleNewConnection()<br/>握手后校验 query token"]
    NewConn -->|"token 无效"| ForceClose["forceClose()"]
    NewConn -->|"token 通过"| W{"WsHandler 路径"}
    W -->|"/ws"| Capture["登记采集 Session"]
    W -->|"/ws/panel"| Panel["登记到 WsDownlink"]
    Capture --> Msg["同一连接持续收发消息<br/>handleNewMessage()"]
    Panel --> Msg
    Msg --> IsPanel{"是否面板连接？"}
    IsPanel -->|"是：Text"| PanelMsg["handlePanelText()<br/>ping / hello / latency"]
    IsPanel -->|"否：采集端"| Control["onControl() 校验后进入 handleControl()"]
    Control --> Op{"控制操作"}
    Op -->|"start"| Start["校验协议与 session<br/>startMedia() → MediaService 队列"]
    Op -->|"offer / ICE / media_status / stop"| MediaControl["校验 session_id 与 media_epoch<br/>mediaControl() → MediaService 队列"]
    Op -->|"ping / clock_offset"| Timing["直接处理心跳 / 时钟信息"]
    Capture -.-> Closed["连接关闭时<br/>handleConnectionClosed() 清理会话"]
    Panel -.-> Closed

    R --> Response["HTTP 响应"]
    Q --> Response
    Clip --> Response
    Agent --> Response
    Static --> Response
~~~

这里的 **Listener → I/O EventLoop → 路由 → Handler** 是框架分发链。WebSocket 分支里的 101 是 HTTP Upgrade 成功响应；从这一步开始，同一个 TCP 连接承载多条 WebSocket frame，直到关闭。项目 token 校验在 101 之后的 <code>handleNewConnection()</code> 中进行。HTTP 的回调、<code>Clips::get()</code> 和 AgentBridge 是不同的 HTTP Handler 实现；<code>WsHandler</code> 是 WebSocketController，按连接事件和消息回调工作。静态面板由 Drogon 内置静态文件路由提供，不是项目自定义 Controller。

**注意：**服务入口把多个 Listener 注册到同一个 <code>drogon::app()</code>。源码未给每个 Listener 配独立路由表，因此不能仅凭 <code>listen_ws</code> 和 <code>listen_http</code> 名称断定某条路由只会出现在其中一个端口。具体绑定地址仍以本次加载的配置为准。

## 五条 HTTP 分支的具体处理流程

上面的总图说明路由入口；下面分别展开截图中的五条 HTTP 路径及其结果。源码位置均以当前仓库实现为准。

### 1. <code>GET /api/runtime</code>

该接口不查数据库，读取服务配置与雷达配置，直接组装 JSON。响应包含 WebSocket 端口、媒体传输开关、雷达实时功能开关、校准 ID 和雷达模式。

~~~mermaid

    A["GET /api/runtime"] --> B["Drogon 按 GET + 路径匹配 registerHandler"]
    B --> C["读取 cfg 与 perceptionConfig().radar"]
    C --> D["组装运行状态 JSON"]
    D --> E["设置 application/json"]
    E --> F["Cache-Control: no-store"]
    F --> G["HTTP 200 JSON 响应"]
~~~

源码：<code>server/apps/server_main.cpp#L325-L335</code>。

### 2. <code>POST /api/clips/query</code>

先检查 Bearer token，再确认 SQLite repository 已配置；随后解析 JSON 查询条件、查库并组装结果。输入错误返回 400，数据库未配置或查询异常返回 503。

~~~mermaid
flowchart TD
    A["POST /api/clips/query"] --> B{"Authorization Bearer token 正确？"}
    B -->|"否"| E401["401 unauthorized"]
    B -->|"是"| C{"SQLite repository 已配置？"}
    C -->|"否"| E503["503 SQLite backend not configured"]
    C -->|"是"| D["解析 JSON<br/>input / context / limit / min_confidence"]
    D --> V{"输入合法？"}
    V -->|"否：JSON 或参数错误"| E400["400 Bad Request"]
    V -->|"是"| Q["SqliteClipRepository::query()"]
    Q --> H{"是否命中片段？"}
    H -->|"有命中"| M["status=matched<br/>组装 clips 与 recommendations"]
    H -->|"无命中"| N["status=no_match<br/>返回空 clips 与 recommendations"]
    M --> OK["200 application/json"]
    N --> OK
    Q -->|"数据库异常"| E503B["503 clip database query failed"]
~~~

输入默认值为 <code>context={}</code>、<code>limit=4</code>、<code>min_confidence=0.75</code>。源码：<code>server/apps/server_main.cpp#L336-L375</code>。

### 3. <code>GET /clips/{file}</code>

Controller 先限制文件名字符与扩展名，阻止路径穿越，再确认文件存在。没有 Range 头时返回完整文件；带 Range 时解析字节范围，合法则返回 206，非法或越界则返回 416。

~~~mermaid

    C -->|"否"| E400["400 Bad Request"]
    C -->|"是"| D{"文件存在？"}
    D -->|"否"| E404["404 Not Found"]
    D -->|"是"| R{"有 Range 请求头？"}
    R -->|"否"| Full["读取整个文件<br/>200 OK"]

    Parse --> Valid{"Range 合法且未越界？"}
    Valid -->|"否"| E416["416 Range Not Satisfiable"]
    Valid -->|"是"| Partial["读取指定字节范围<br/>设置 Content-Range"]

源码：<code>server/libs/core/range_controller.hpp#L7-L15</code>、<code>server/libs/core/range_controller.cpp#L16-L109</code>。当前实现把本次响应字节读入内存后设置响应体；使用 Range 时只读取请求范围。

### 4. <code>/internal/agent/state</code>、<code>/bind</code>、<code>/judgments</code>

这组三条内部接口要求请求来自回环地址并携带 Agent Bearer token。<code>GET /state</code> 直接返回当前绑定状态；写入请求必须是 POST、JSON 对象且不超过 32 KiB，再进入 AgentBridge 工作队列处理。

    B -->|"否"| E401["401 unauthorized"]
    B -->|"是"| C{"GET /state？"}
    C -->|"是"| State["读取 AgentBridge::state()"]
    State --> OK["200 JSON"]
    C -->|"否"| D{"POST 且 body ≤ 32 KiB？"}
    D -->|"否"| E400["400 method_or_size"]
    D -->|"是"| J{"body 是 JSON object？"}
    J -->|"否"| E400J["400 invalid_json"]
    J -->|"是"| O["bind 路径补 op=bind<br/>judgments 路径移除 op"]
    O --> Q{"工作队列已关闭或达到 32 项？"}
    Q -->|"是"| E503["503 bridge_full_or_stopped"]
    Q -->|"否"| Worker["AgentBridge worker 校验 session、epoch、binding、证据与序号"]
    Worker --> Result["HTTP 回调返回处理结果<br/>200 / 400 / 409 / 410"]
~~~

源码：<code>server/libs/core/agent_bridge.cpp#L145-L159</code>；队列处理与业务校验见 <code>#L41-L113</code>。这里的 POST 响应由 worker 完成后通过原始 Drogon response callback 返回。

### 5. 面板静态路径

静态页面不经过项目自定义 Controller。Drogon 使用 <code>cfg.panel_dir</code> 作为 document root；启用 implicit page 后，访问根路径可返回目录首页，其他静态资源按相对路径读取。

~~~mermaid
flowchart TD
    A["浏览器 GET / 或静态资源路径"] --> B["Drogon 静态文件路由"]
    B --> C["映射到 cfg.panel_dir 下的文件"]
    C --> D{"目标文件存在？"}
    D -->|"是"| E["返回 HTML / JS / CSS / 图片"]
    D -->|"否"| F["返回未找到响应"]
~~~

源码：<code>server/apps/server_main.cpp#L383-L385</code>。静态目录和入口文件来自当前启动配置；YAML 示例不代表服务实际加载值。
