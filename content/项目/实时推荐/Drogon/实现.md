# Drogon 服务端源码实现

> 本文对照当前服务端源码说明 Drogon 的装配点、路由、线程边界和关停顺序。流程图见 [流程.md](流程.md)。源码位置相对 <code>D:\csevent</code> 或 Linux 仓库 <code>/home/lth/csevent</code>；服务器工作树与本地工作树可能有未提交差异。

## 1. Drogon 的职责

项目把 Drogon 用作 HTTP/WebSocket 服务框架：

- WebSocket 接入采集端和网页面板，完成 token 校验、会话控制和 WebRTC 信令中转。
- HTTP 提供运行信息、SQLite 片段查询、视频 Range 下载和静态面板。
- <code>server_main.cpp</code> 负责把配置、路由、媒体接收和业务处理模块装配起来，并管理服务启停。

媒体接收、感知、ASR/VLM 和推荐逻辑由项目自己的 <code>server/libs/</code> 模块完成。源码没有用 Drogon ORM 作为推荐数据库层：片段数据由项目的 <code>SqliteClipRepository</code> 与 SQLiteCpp 访问。

Drogon 依赖由 <code>server/libs/core/CMakeLists.txt</code> 的 <code>find_package(Drogon CONFIG REQUIRED)</code> 引入，并链接 <code>Drogon::Drogon</code>。vcpkg manifest 也列出 <code>drogon</code>。

## 2. 入口与初始化顺序

服务器入口为 <code>server/apps/server_main.cpp</code>：

1. <code>main()</code> 查询 <code>TACTICLENS_CONFIG</code>；未设置时读取 <code>config/server.yaml</code>。配置路径按进程当前工作目录解析，因此服务启动时的工作目录也很重要。
2. 读取监听地址、token、归档路径、媒体/感知开关及 VLM/语音配置。
3. 配置 <code>AgentBridge</code> 和延迟日志；创建 EventBus、SQLite 推荐后端、GameState、FastLane、VoiceLane 与 TimerLane。
4. 启动 Archiver 和 IngestPipeline；如果启用媒体功能，则初始化 MediaService。
5. 按配置启用 Perception、VLM、ReplayInjector 等模块。
6. 注册 HTTP handlers、Drogon listeners、WebSocketController 与静态面板目录。
7. 调用 <code>drogon::app().run()</code> 进入服务循环。

Drogon 在同一个 <code>drogon::app()</code> 上注册 handlers、Controller 和两组监听地址：<code>cfg.listen_addr:cfg.listen_port</code> 与 <code>cfg.listen_http_addr:cfg.listen_http_port</code>。源码在添加第一个 listener 时设置 <code>setThreadNum(2)</code>。路由注册属于这个 app；源码没有为某组 listener 单独分配路由表，因此不要仅凭变量名推断两个端口分别只服务 WebSocket 或 HTTP。运行端口和开关必须以 systemd 实际传入的 <code>TACTICLENS_CONFIG</code> 及进程状态为准，不能从某个 YAML 示例直接推断。

## 3. HTTP 与 WebSocket 路由

<a id="http-与-websocket-路由"></a>

| 协议 | 路由 | 实现位置 | 行为 |
|---|---|---|---|
| WebSocket | <code>/ws</code> | <code>server/libs/core/ws_handler.hpp</code>、<code>ws_handler.cpp</code> | 采集端会话；token 在连接参数中校验；处理 start、ping、clock_offset、stop 和 WebRTC offer/ICE 信令。 |
| WebSocket | <code>/ws/panel</code> | <code>ws_handler.hpp</code>、<code>ws_handler.cpp</code>、<code>downlink.cpp</code> | 面板专用连接；token 校验后登记到 WsDownlink，不创建采集 Session。接收 ping、hello、延迟采样等文本消息。 |
| HTTP GET | <code>/api/runtime</code> | <code>server/apps/server_main.cpp</code> | 返回 websocket 端口、媒体传输开关和雷达配置状态。 |
| HTTP POST | <code>/api/clips/query</code> | <code>server/apps/server_main.cpp</code> | 校验 <code>Authorization: Bearer ...</code>，解析查询条件并访问 SQLite repository，返回 clips 和 recommendations。未配置 SQLite 时返回 503。 |
| HTTP GET | <code>/clips/{file}</code> | <code>server/libs/core/range_controller.hpp</code>、<code>range_controller.cpp</code> | 校验文件名和扩展名，支持完整读取、<code>Range</code> 部分读取，以及 400/404/416 响应。 |
| HTTP | <code>/internal/agent/state</code>、<code>bind</code>、<code>judgments</code> | <code>server/libs/core/agent_bridge.cpp</code> | 仅接受回环来源和 agent Bearer token；写入类请求进入 AgentBridge 工作队列。 |
| HTTP GET | <code>/</code> 等静态路径 | <code>server/apps/server_main.cpp</code> | <code>setDocumentRoot(cfg.panel_dir)</code> 与 implicit page 提供面板文件。 |

### WebSocket 消息处理

<code>WsHandler</code> 继承 <code>drogon::WebSocketController&lt;WsHandler&gt;</code>，声明 <code>/ws</code> 与 <code>/ws/panel</code> 两个路径。新连接先校验 query 参数 <code>token</code>：

- <code>/ws/panel</code> 登记进 <code>WsDownlink</code>，随后处理面板 ping、槽位数 hello 和延迟采样。
- <code>/ws</code> 创建 Session；消息通过统一 control 校验后进入 <code>handleControl()</code>。
- <code>start</code> 要求协议版本 2、<code>media_transport=webrtc</code>、<code>cs2/oopz</code> 两路进程音频和独立 ASR 输入。
- <code>webrtc_offer</code>、<code>webrtc_ice</code>、<code>media_status</code> 按 session_id 与 media_epoch 校验后投递给 MediaService。
- <code>stop</code> 将最终状态投递给 MediaService；WebSocket 断开时也会关闭对应媒体会话。

**当前代码的数据通道边界：**WebSocket 二进制帧经 wire decoder 解码后，只接受 Control 类型；其它类型会被拒绝并提示媒体必须使用 WebRTC。源码仍设置 WebSocket 消息大小上限以匹配 wire 协议常量，但这不表示此版本通过 WebSocket 上传音视频。

## 4. MediaService 与处理线程边界

<code>startMedia()</code> 和 <code>mediaControl()</code> 只将命令放入 MediaService 的命令队列。MediaService 自己创建工作线程，在线程中处理 <code>attach</code>、offer、ICE、stop，并轮询 WebRtcReceiver。

收到 WebRTC 媒体后：

- 视频回调将解码帧放入容量为 1 的视频队列，MediaService 的 <code>drain()</code> 再将帧送入 <code>IngestPipeline::onMediaFrame()</code>。注册的 Perception 与 VLM 帧 tap 各自接收并异步处理。
- CS2 与 Oopz 音频分别进入有界队列和 AudioAssembler；完整音频块发布为 EventBus <code>AudioChunk</code>，可同时写入原始音频存档。
- FastLane 消费 <code>CvEvent</code>、更新 GameState 并触发推荐和槽位决策，再由 <code>WsDownlink</code> 推送到面板。
- Perception 的 OCR/回合信息可直接下发；其他观察结果可交给 AgentBridge。VLM 结果也可通过下行通道发送。

这层隔离让网络 handler 主要做鉴权、协议校验和命令投递。处理图像、音频组装、推理和推荐的工作位于专门服务或处理车道中。

## 5. 当前实现的边界与注意点

- <code>/api/clips/query</code> 在 Drogon handler 中同步解析 JSON 并调用 <code>sqlite_repo-&gt;query(q)</code>。数据库查询变慢或并发提高时，需要关注它对 HTTP 响应延迟和 Drogon 工作线程的影响。
- <code>/clips/{file}</code> 当前按请求范围把文件内容读入内存后构造响应；客户端使用 Range 请求时，单次读取范围受限。无 Range 请求会读取完整文件。
- <code>setThreadNum(2)</code> 是源码配置，不是并发容量或压测结果；当前文档没有据此给出吞吐量结论。
- <code>/ws</code> 与 <code>/ws/panel</code> 都使用 query 参数 token；HTTP 查询和 AgentBridge 则分别采用 Bearer token 校验。
- 代码中的 <code>started</code> 表示服务端接受媒体会话并排入初始化，不代表 WebRTC 已连接、视频已收帧或音频已经被 ASR 消费。

## 6. 优雅关停顺序

<code>drogon::app().run()</code> 返回后，入口按依赖关系逐步收尾：

1. 停止 ReplayInjector、MediaService 和状态脚本驱动器。
2. 停止 Perception、AgentBridge 与 VLM。
3. 请求 FastLane、VoiceLane、TimerLane 停止，并等待 VoiceChain 的 HTTP 工作结束。
4. 关闭 EventBus，等待消费者退出。
5. 停止延迟日志，返回进程。

这样可以避免生产者仍在发布事件时，先销毁其依赖的总线或处理器。
