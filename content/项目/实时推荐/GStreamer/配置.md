# WebRTC 配置说明

> 本页整合客户端配置结构、YAML 示例和服务端建链配置。客户端字段与默认值以 <code>D:\csevent\client\src\client_config.hpp</code> 为准，读取和校验规则以 <code>D:\csevent\client\src\client_config.cpp</code> 为准。启动顺序见 [启动.md](启动.md)，媒体建链见 [WebRTC.md](WebRTC.md)，客户端主流程和管线源码见 [WebRTC实现.md](WebRTC实现.md)，信令和回调源码见 [WebRTC信令与回调实现.md](WebRTC信令与回调实现.md)。

## 配置文件与加载入口

| 配置文件 | 何时使用 | 说明 |
|---|---|---|
| <code>config/client.webrtc.yaml</code> | <code>run_media_client.ps1</code> 的 <code>-Config</code> 默认值；[启动.md](启动.md) 的 Run 示例也显式指定它 | Windows WebRTC 客户端候选配置，示例运行 30 秒 |
| <code>config/client.yaml</code> | 直接运行 <code>capture-client.exe</code> 且未传配置路径时 | 除 <code>run_seconds</code> 为 0 外，其余与 WebRTC 示例一致 |


客户端相对路径从进程当前工作目录解析。媒体启动脚本会切换到 <code>D:\csevent</code> 仓库根目录，因此示例中的 <code>config/...</code> 和报告路径都相对于该目录。直接运行客户端时，应在仓库根目录执行，或传入正确的配置路径。

<code>main.cpp</code> 的普通启动默认读取 <code>config/client.yaml</code>；媒体启动脚本默认传入 <code>config/client.webrtc.yaml</code>。SelfTest、Probe 和 UplinkTest 默认也使用 <code>config/client.webrtc.yaml</code>。实际加载哪份文件由启动参数决定，不能只凭 YAML 文件名推断运行时配置。

<code>loadClientConfig()</code> 在文件缺失或读取失败时会记录警告并返回失败，配置对象保留结构体默认值；是否继续运行由调用入口决定。配置文件存在时，只覆盖 YAML 中出现的字段。

## WebRTC 客户端 YAML

下面是 <code>D:\csevent\config\client.webrtc.yaml</code> 的当前内容。它是候选运行配置；服务端地址、鉴权值、运行时长和报告路径应按本次运行调整。

~~~yaml
# Candidate only: the production server must explicitly confirm protocol v2.
server_url: ws://10.23.66.160:9003/ws
token: "dev-token"
source: wgc
capture_target: window
window_process: cs2
audio_capture_mode: process
audio_cs2_process: cs2
audio_oopz_process: oopz
audio_allow_system_fallback: false
asr_input_mode: separate
heartbeat_s: 5
run_seconds: 30
media:
  transport: webrtc
  video_backend: gstreamer  # native = raw WGC -> appsrc comparison
  signaling_timeout_ms: 10000
  report_path: var/media-migration-20261025/client-report.json
  video:
    width: 1440
    height: 1080
    target_fps: 30
    bitrate_kbps: 8000
  audio:
    packet_ms: 20
    bitrate_kbps_per_track: 48
    max_pending_packets_per_source: 10
~~~

<code>config/client.yaml</code> 与上面的 WebRTC YAML 仅 <code>run_seconds</code> 不同，设为 <code>0</code>。运行脚本的默认配置仍是 <code>client.webrtc.yaml</code>；若要常驻运行，需要显式把 <code>run_seconds</code> 设为 <code>0</code>。YAML 中的 <code>dev-token</code> 是仓库示例值，客户端与服务端实际使用时必须一致。

## 客户端字段与结构体默认值

以下默认值来自 <code>ClientConfig</code>。YAML 没写某个字段时，解析器保留对应默认值。表中也标出只被解析、但当前 WebRTC 链路没有消费的兼容字段；媒体队列与帧率等运行值以 WebRTC 专属的 <code>media.*</code> 字段为准。

### 顶层字段

| YAML 字段 | 结构体默认值 | 作用 |
|---|---:|---|
| <code>server_url</code> | <code>ws://127.0.0.1:9000/ws</code> | WebSocket 信令与控制连接地址；不是 RTP 媒体直连地址 |
| <code>token</code> | <code>dev-token</code> | WebSocket 鉴权值，必须与服务端一致 |
| <code>source</code> | <code>wgc</code> | 客户端输入源，结构体注释列出 <code>wgc</code> 和 <code>replay</code> |
| <code>replay_dir</code> | 空字符串 | 结构体注释中的重放目录；当前 WebRTC 校验要求 <code>source: wgc</code>，不使用此字段 |
| <code>replay_speed</code> | <code>1.0</code> | 结构体注释中的重放速度倍率；当前 WebRTC 路径不使用 |
| <code>fps_base</code> | <code>1</code> | 保留的基础采样帧率字段；当前 WebRTC 帧率由 <code>media.video.target_fps</code> 控制 |
| <code>jpeg_quality</code> | <code>70</code> | 保留的 JPEG 质量字段；当前 WebRTC 视频链路不使用 JPEG |
| <code>queue_frames_bound</code> | <code>8</code> | 保留的旧队列字段；当前 WebRTC Native 视频队列容量固定为 1，GStreamer 路径不读此值 |
| <code>queue_audio_bound</code> | <code>32</code> | 保留的旧队列字段；当前 WebRTC 每路音频队列由 <code>media.audio.max_pending_packets_per_source</code> 设置 |
| <code>heartbeat_s</code> | <code>5</code> | WebSocket 心跳间隔，单位秒 |
| <code>session_id</code> | 空字符串 | 保留的配置字段；当前 WebRTC 运行不读取此字段，WebSocket 控制连接在连接成功时自行生成会话 ID |
| <code>run_seconds</code> | <code>0</code> | 大于 0 时运行指定秒数后退出；0 表示持续运行 |
| <code>capture_target</code> | <code>window</code> | 采集目标；结构体注释列出 <code>window</code> 和 <code>monitor</code> |
| <code>window_process</code> | <code>cs2</code> | 按进程名定位窗口；进程名大小写不敏感，<code>cs2</code> 与 <code>cs2.exe</code> 均可 |
| <code>audio_capture_mode</code> | <code>auto</code> | 音频模式，可选 <code>auto</code>、<code>process</code>、<code>system</code>；WebRTC 不允许 <code>system</code> |
| <code>audio_cs2_process</code> | <code>cs2</code> | CS2 进程音频来源名 |
| <code>audio_oopz_process</code> | <code>oopz</code> | Oopz 进程音频来源名 |
| <code>audio_allow_system_fallback</code> | <code>false</code> | 是否允许进程采集失败后回退到系统混音；WebRTC 必须为 <code>false</code> |
| <code>asr_input_mode</code> | <code>separate</code> | ASR 音频输入组织方式，可选 <code>mixed</code>、<code>separate</code>；WebRTC 要求 <code>separate</code> |
| <code>audio_debug_dir</code> | 空字符串 | 旧式 WASAPI 路径的 PCM 与时间诊断目录；当前 WebRTC <code>IndependentAudioSource</code> 不读取此字段 |

### media 字段

YAML 将媒体参数分成 <code>media.video</code> 和 <code>media.audio</code> 两层；C++ 的 <code>ClientConfig::Media</code> 内部将它们保存为成员字段。

| YAML 字段 | 对应成员 | 默认值 | 作用与约束 |
|---|---|---:|---|
| <code>media.transport</code> | <code>media.transport</code> | <code>webrtc</code> | 当前分支仅支持 <code>webrtc</code> |
| <code>media.video_backend</code> | <code>media.video_backend</code> | <code>gstreamer</code> | 视频采集后端，可选 <code>gstreamer</code>、<code>native</code> |
| <code>media.signaling_timeout_ms</code> | <code>media.signaling_timeout_ms</code> | <code>10000</code> | WebRTC 能力协商与 ICE 等待超时，范围 100–60000 毫秒 |
| <code>media.report_path</code> | <code>media.report_path</code> | 空字符串 | 客户端结束报告路径；相对当前工作目录解析 |
| <code>media.video.width</code> | <code>media.width</code> | <code>1440</code> | 当前固定为 1440 |
| <code>media.video.height</code> | <code>media.height</code> | <code>1080</code> | 当前固定为 1080 |
| <code>media.video.target_fps</code> | <code>media.target_fps</code> | <code>30</code> | 目标帧率，范围 1–60 |
| <code>media.video.bitrate_kbps</code> | <code>media.bitrate_kbps</code> | <code>8000</code> | 视频目标码率，单位 kbps，范围 100–50000 |
| <code>media.audio.packet_ms</code> | <code>media.packet_ms</code> | <code>20</code> | 音频包时长，当前只能设为 20 毫秒 |
| <code>media.audio.bitrate_kbps_per_track</code> | <code>media.audio_bitrate_kbps</code> | <code>48</code> | 每路 Opus 音频码率，单位 kbps，范围 6–128 |
| <code>media.audio.max_pending_packets_per_source</code> | <code>media.max_audio_packets</code> | <code>10</code> | 每个音频来源的待处理包上限，范围 1–25 |

## 解析规则与 WebRTC 约束

客户端解析器对 YAML 做类型转换，并执行以下校验：

- <code>audio_capture_mode</code> 只能是 <code>auto</code>、<code>process</code>、<code>system</code>；<code>asr_input_mode</code> 只能是 <code>mixed</code> 或 <code>separate</code>。
- WebRTC 要求 <code>source: wgc</code>、<code>capture_target: window</code>、<code>asr_input_mode: separate</code>；音频不能使用 <code>system</code> 模式或系统混音回退，两路进程名必须非空。示例把模式明确设为 <code>process</code>。
- <code>media</code>、<code>media.video</code>、<code>media.audio</code> 必须是映射；这些层级出现解析器不认识的字段会报错。顶层其他未知字段当前不会由这段解析逻辑拒绝。
- 存在 <code>media</code> 时，视频分辨率必须是 1440×1080；帧率、码率、音频包数和信令超时必须落在上表范围内，音频包时长必须为 20 毫秒。
- WebRTC 启动时还需要服务端返回有效的协议 v2 与 WebRTC 确认；仅修改客户端 YAML 不会完成服务端建链。

## ICE 网络配置边界

当前客户端和服务端候选 YAML 没有 STUN/TURN 服务器地址，也没有固定 ICE UDP 端口范围。Candidate 类型中出现 <code>srflx</code> 或 <code>relay</code> 只是在说明 ICE 协议类型，不表示项目已经配置或验证公网映射、NAT 穿透或 TURN 中继。

不要只向 YAML 添加任意 STUN/TURN 键：客户端解析器没有对应的字段和 PeerConnection 配置实现。跨网与 TURN 支持需要先补齐代码，再进行网络验收。建链流程见 [ICE 建链流程](WebRTC.md#ice-建立连接路径)。
