# 雷达地图纹理被误识别为 C4

## 涉及文件

- `tools/review_c4_false_positives.py`：预测与人工框逐例对照。
- `tools/rebalance_rect_c4.py`：困难负样本筛选和训练快照加权。
- `tools/train_rect_yolo.py`：候选模型训练。
- `tools/eval_rect_operating_point.py`：固定阈值的一对一匹配统计。
- `tools/check_rect_onnx.py`：PyTorch/ORT 一致性检查。

## 问题

六类雷达模型在固定 108 张验证图上，C4 的 TP=29、FP=10、FN=2。复核后发现，9 个误报都来自雷达裁图约 `(179,51)` 的同一块地图背景纹理。它在不同帧重复出现，模型也反复把它当成 C4。

剩下 1 个误报并不是背景混淆：人工框和预测框都指向 C4，但中心差约 6.12px，IoU=0.4351，低于匹配阈值 0.5，因此同时计为 FP 和 FN。

## 修改前

原训练快照有 429 张独立图像，使用原始采样，没有额外提高这类纹理和清晰独立 C4 的出现频率。此时的固定阈值为 conf=0.25、NMS IoU=0.45、同类匹配 IoU≥0.5。

从训练条目的角度，原来相当于下面的逻辑，省略训练时的数据增强：

```python
# 原快照：每张训练图只有一个条目，没有指定模式的额外副本。
for frame in train_members:
    add_training_entry(frame.image, frame.label)
```

`add_training_entry` 是示意名称。后面的改动是在保持原条目的基础上，为选中的图和标签增加副本。

我没有先在输出端硬编码“这个坐标永远不是 C4”，因为真实 C4 也可能出现在那里；也没有删掉难样本或直接把标注改成预测框。

## 修改后

### 1. 从训练集筛选确实能教给模型的样本

我先复用已经保存的验证预测找出错误模式，再仅在原训练集挖掘候选。下面是 `rebalance_rect_c4.py` 的核心条件，变量准备已省略：

```python
TEXTURE = (169., 42., 189., 62.)

clear = all(gap(TEXTURE, g[:4]) >= 2 for g in gt)
players = [g for g in gt if g[4] != 5]
isolated = [
    g for g in gt
    if g[4] == 5
    and gap(TEXTURE, g[:4]) >= 8
    and all(gap(g[:4], p[:4]) >= 2 for p in players)
]
visible = clear and mae <= 20

category = None
repeat = 1
if visible and isolated:
    category = 'isolated_c4_and_clear_texture'
    repeat = 3
elif visible and score is not None and score >= .25:
    category = 'texture_hard_negative'
    repeat = 2

if image_hash in val_hashes:
    category = None
    repeat = 1
```

类别 5 是 c4_icon。`clear` 要求纹理没有被真实目标框遮住，`mae` 是局部纹理与参考模式的像素差，`score` 是基线模型在该区域给出的 C4 分数。

优先选择“纹理可见且真实 C4 独立存在”的图，每轮出现 3 次；只符合困难纹理负样本的图，每轮出现 2 次。其他图保留 1 次。这个负样本是局部背景模式，整张图仍保留所有真实类别框，不能为了教背景就把标签清空。

### 2. 加权通过复制现有图像和标签实现

脚本先复制原快照，再为选中训练样本增加字节一致的副本。下面保留实际复制逻辑的结构：

```python
for r in records:
    if r['sampling_frequency'] == 1:
        continue
    for n in range(1, r['sampling_frequency']):
        stem = f'{r["stem"]}__repeat{n}'
        for kind, ext in [('images', 'png'), ('labels', 'txt')]:
            shutil.copy2(
                args.data / kind / 'train' / f'{r["stem"]}.{ext}',
                args.out / kind / 'train' / f'{stem}.{ext}'
            )
        members.append(dict(originals[r['stem']], stem=stem,
                            repeated_from=r['stem'], repeat_index=n))
```

最终是 21 张困难负样本各多 1 份，33 张清晰 C4 样本各多 2 份，总共多 87 份：

```text
429 + 21 × 1 + 33 × 2 = 516 个训练条目
独立图像仍然是 429 张，没有新增人工标注
```

原 108 张验证图和 6 秒时间组隔离边界保留。脚本检查验证元数据、时间组与原文件：

```python
assert result['splits']['val'] == manifest['splits']['val']
train_groups = {m['group'] for m in members}
assert not train_groups.intersection(result['validation_groups'])
assert source_hashes(manifest) == before
```

另外逐字节核对原图和标签，记录数据快照哈希。验证帧的相同字节副本不得进入增采样池。

## 为什么这样改

重复采样提高了模型每轮看到指定混淆模式的频率：多看“这里是背景”，同时多看与玩家不重叠的真实 C4，帮助区分背景与图标。只加负样本可能增加压低 C4 输出的倾向，所以我同时提高了清晰正例频率，并一起观察召回。

这次是数据采样策略修改，运行时没有增加特殊坐标屏蔽，也没有直接修改模型网络结构。误报变少是否值得，需要看固定阈值下的 TP、FP、FN，而不只看总体 mAP。

## 验证

2026-10-28，从同一本地预训练权重重新训练候选，固定验证规则对比：

| C4 指标 | 原模型 | 加权候选 |
| --- | ---: | ---: |
| conf=0.25：TP | 29/31 | 27/31 |
| conf=0.25：FP | 10 | 1 |
| conf=0.25：已知纹理 FP | 9 | 0 |
| conf=0.25：Precision | 74.4% | 96.4% |
| conf=0.40：FP | 2 | 0 |

召回由 29/31 降到 27/31，约从 93.5% 降到 87.1%，因此我记录为误报改善伴随召回损失。108 张验证图的 PyTorch/ORT 预测框 414/414 同类匹配，候选没有替换正式模型，运行阈值未改。

已知验证误报参与了纹理区域选择，这批验证集实际上参与过调优，后面仍需独立新会话检验。重复采样也增加了每轮优化步数，所以这不是严格固定总步数的策略消融。

## 总结

我先把 10 个统计误报还原到图像，区分出固定纹理混淆和框定位偏差，再只对训练集做困难负样本与清晰正例加权。结果是固定验证集误报从 10 降到 1，但召回也下降，因此保留为候选继续评估。数据条目增加、独立样本增加和正式上线是三件不同的事，需要分别记录。
