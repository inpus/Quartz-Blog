# 雷达地图纹理被误识别为 C4

## 涉及文件

| 文件 | 作用 |
| --- | --- |
| `tools/review_c4_false_positives.py` | 复用预测结果，逐例对照人工标注与局部图像 |
| `tools/rebalance_rect_c4.py` | 挖掘训练集困难负样本并生成加权快照 |
| `tools/train_rect_yolo.py` | 候选 YOLO 模型训练 |
| `tools/eval_rect_operating_point.py` | 固定阈值下统计 TP/FP/FN |
| `tools/check_rect_onnx.py` | 检查 PyTorch 与 ONNX 预测一致性 |

## 背景与现象（S）

双会话六类雷达模型在 108 张固定验证图上，以 `conf=0.25`、NMS IoU=0.45、同类匹配 IoU≥0.5 评估，C4 为 TP=29、FP=10、FN=2。整体检测指标较好，但 C4 误报可能给下游错误的炸弹位置信息，需要逐例解释。

## 要达到的目标（T）

确定误报究竟来自背景混淆、标注问题还是定位偏差，再针对根因优化。保持原标注和验证快照可追溯，观察误报改善是否牺牲召回。

## 排查与根因（A）

直接复用已经保存的 `val_detections.json` 和 operating point 结果，提取未匹配 C4 预测，没有先改阈值或重训。

人工图像对照得到两种情况：

- 9 个误报集中在雷达裁图约 `(179,51)`，对应同一固定地图背景纹理，置信度约 0.254–0.618。这是相同背景模式在多帧中重复出现。
- 另 1 个预测和人工框都指向可见 C4，但中心差约 6.12px，IoU=0.4351，低于 0.5；评估同时记为 FP 与 FN。这项统计不能直接解释为把背景识别成 C4。

因此优化重点是固定纹理混淆，同时保留定位偏差样本的原始解释，不为降低误报数直接改标。

## 如何解决

只从原训练集挖掘样本，保留 429 张独立图像及全部真实标签：

1. 选出 21 张纹理清晰、目标不遮挡该区域的困难负样本，每轮出现 2 次。
2. 选出 33 张 C4 与玩家图标分离、纹理清晰的正样本，每轮出现 3 次。
3. 其余训练图保留。新增 87 份副本逐字节对应原训练文件，有效训练样本数变为 516，独立图像仍是 429。
4. 固定原 108 张验证图及 6 秒时间组隔离边界，训练副本不包含验证帧或其相同字节图像。

从同一本地预训练权重重训候选模型，使用相同阈值与一对一匹配规则对比，随后做 ONNX 导出一致性检查。

## 验证与结果（R）

2026-10-28 的固定验证集结果：

| C4 指标 | 原模型 | 加权候选 |
| --- | ---: | ---: |
| conf=0.25：正确匹配 | 29/31 | 27/31 |
| conf=0.25：总误报 | 10 | 1 |
| conf=0.25：已知纹理误报 | 9 | 0 |
| conf=0.25：Precision | 74.4% | 96.4% |
| conf=0.40：总误报 | 2 | 0 |

在 conf=0.25 下，召回由 29/31 降到 27/31，约从 93.5% 降到 87.1%。误报减少伴随召回代价，不能只用“误报清零”概括。

全部 108 张验证图的 PyTorch/ORT 输出检查通过，预测框 414/414 同类匹配。候选没有替换正式服务，也没有修改运行阈值。

这轮根据已知验证误报确定了纹理区域，因此验证集参与过调优；结果是同一固定数据上的优化对照，最终泛化效果仍需要独立新会话。重复采样也增加了每轮优化步数，不能将收益完全归因为采样策略本身。

## 可以复用的经验

先把指标还原到具体图像，再决定改数据、阈值还是模型。困难负样本要保留图中的真实正例；重采样数量与独立数据量分开记录。评估改进同时查看误报、漏检和部署状态，避免离线候选结果被误写成线上收益。
