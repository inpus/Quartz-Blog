# 音频时间戳抖动导致重采样状态反复重置

## 涉及文件

- `client/src/audio_packet_clock.hpp`：设备帧位置、QPC、分段和时间估算。
- `client/src/capture_audio.cpp`：采集包接入及重采样状态切换。
- `client/src/resampler.cpp`：跨包滤波状态。
- `client/src/raw_audio_recorder.cpp`：原始包位置和 PCM 留存。

## 问题

音频设备帧位置连续时，QPC 偏移或 `DATA_DISCONTINUITY` 标志也可能触发重新锚定。原处理把这些情况都当成音频断点，反复清掉重采样状态，反而打断了有效 PCM 的处理。

## 修改前

按当时判断规则简化，问题相当于下面的写法：

```cpp
if (discontinuity || timestamp_error || qpc_jump) {
    // 按断流处理，重建时间锚并清掉滤波状态。
    reset_resampler();
    reset_clock();
}
```

这里的函数名只表示操作，没有逐字还原旧实现。错误在于把“时钟信息不可靠”和“样本确实缺失”当成了同一件事。

举个计算例子：上一包从设备帧 4800 开始，有 480 帧，下一包应该从 5280 开始。如果下一包确实从 5280 开始，样本是连续的；即使 QPC 多偏了 30ms，也没有理由因此清空 FIR。

## 修改后

我用设备帧位置判断数据是否连续，用 QPC 建立时间锚。`AudioPacketClock::observe()` 的关键判断为：

```cpp
if (discontinuity) ++data_discontinuity_flags;
if (!valid) {
    ++timestamp_errors;
    ++estimated_packets;
}

const double expected = origin_ + double(frames_) / rate_;
const bool device_break = valid && have_device_ && device != device_end_;
const bool qpc_break = valid && anchored_ &&
                       std::abs(stamp - expected) > 0.025;
if (qpc_break) ++qpc_outliers;

if (device_break) {
    if (device > device_end_) gap_frames += device - device_end_;
    else overlap_frames += device_end_ - device;
}
const bool segment = !anchored_ || device_break ||
                     (qpc_break && !have_device_);
```

注意 `discontinuity` 只计数，不直接令 segment 为 true。已有有效设备位置时，单独的 qpc_break 也不会开新段；如果连设备位置依据都没有，才需要用 QPC 异常判断重新建立时间锚。

确定分段后，时间和样本位置这样推进：

```cpp
if (segment) {
    if (anchored_) ++reanchors;
    origin_ = valid ? stamp : arrival - double(frames) / rate_;
    frames_ = 0;
    anchored_ = true;
}

const double start = origin_ + double(frames_) / rate_;
frames_ += frames;
if (valid) {
    device_end_ = device + frames;
    have_device_ = true;
} else if (have_device_) {
    device_end_ += frames;
}
return {start, segment, !valid};
```

`valid` 表示本包位置/时间信息可用，和 PCM 内容是否有效分开处理。信息无效但已有设备连续性时，按已收到的帧数推进；首次无有效时间锚时，用“到达时间减包长”估计起点，并返回 estimated 标记。

## 为什么这样改

连续音频的时间可以从一个可信起点加累计样本数推算，不必让每包 QPC 抖动直接改变时间轴。48kHz 下，每增加 480 帧就前进 10ms，设备帧计数比回调什么时候被调度更贴近音频内容。

修改后，只有首次建立时钟、确认设备位置跳变，或缺少设备位置依据且 QPC 明显跳变时才开新段。重采样器不再因为一个告警标志频繁丢掉滤波历史。

同时我把诊断计数拆开：时间戳错误、QPC 异常、重新锚定、实际 gap/overlap 分别统计。`DATA_DISCONTINUITY` 次数不能再直接当成丢包数。

## 验证

2026-10-17 的自动验证覆盖时间戳异常时保留 PCM、设备位置间隙与重叠、原始录音和停止排空。当轮客户端总计 16 项用例、16,313 个断言通过。

原始包日志保存 device/QPC/flags 和 WAV 偏移，便于复查估算与真实间隙。估算时间一直带标记，不把它当作精确设备时间。

## 总结

我把音频连续性和时间可信度拆开了：设备位置负责判断样本有没有断，QPC 负责建立时间锚。时间戳不可靠时尽量保留 PCM，并标出估算；确认数据断点时再分段。这样既避免人为制造断流，也保留了排查真实丢样本的证据。
