# 音频时间戳抖动导致重采样状态反复重置

## 涉及文件

| 文件 | 作用 |
| --- | --- |
| `client/src/audio_packet_clock.hpp` | 结合设备帧位置与 QPC 判断包的时间和连续性 |
| `client/src/capture_audio.cpp` | 将时钟判断接到采集、分段与重采样流程 |
| `client/src/resampler.cpp` | 需要跨包保留的 FIR 滤波状态 |
| `client/src/raw_audio_recorder.cpp` | 留存原始包位置、标志和 PCM 证据 |

## 背景与现象（S）

2026-10-17 音频采集修正中发现，QPC 时间偏移或 WASAPI 的 `DATA_DISCONTINUITY` 标志可能触发重新锚定并清空重采样状态。但时间信息异常并不必然意味着 PCM 样本丢失；这样处理会主动打断原本连续的音频。

## 要达到的目标（T）

区分“样本真的不连续”与“时间戳需要估算”。尽量保留有效 PCM，同时让真实缺口、重叠和时间估算在诊断信息中可见。

## 排查与根因（A）

采集有两类不同证据：设备帧位置描述样本走到了哪里，QPC 描述该位置对应的时间。旧判断将两者混用，只要时间异常就按数据断点处理。

假设上一包结束于设备位置 4800，下一包从 4800 开始，样本本身连续。即使 QPC 突然偏移，也不应直接丢弃下一包或重新初始化 FIR。反过来，若有效设备位置从 4800 跳到 5280，就有明确的样本间隙证据，需要建立新段。

以上数值用于解释规则，并非项目某次设备日志的摘录。

## 如何解决

将连续性判断集中到 `AudioPacketClock`：

1. 用有效设备帧位置与预期结束位置比较，确定是否有真实跳变；分别统计 gap 与 overlap。
2. 用 QPC 建立时间锚。设备位置保持连续时，单独的 QPC 偏移只增加异常计数，不反复重置重采样器。
3. 单独记录 `DATA_DISCONTINUITY` 标志，不将其出现次数直接解释为实际丢包数。
4. `TIMESTAMP_ERROR` 时保留 PCM；已建立连续位置时沿用样本计数推算，首次无法定位时用到达时间估算，并标注 estimated。
5. 确认设备位置跳变或需要开启新段时，才执行相应的分段与滤波收尾。

元数据分开记录 `timestamp_errors`、`qpc_outliers`、`clock_reanchors`、`device_gap_frames`、`device_overlap_frames` 等。原始包日志另保存设备位置、QPC、flags 和 WAV 偏移，便于回查。

## 验证与结果（R）

2026-10-17 的客户端验证覆盖时间戳异常时保留 PCM、设备间隙/重叠及原始录音排空。当日汇总记载 Windows 16 项用例、16,313 个断言通过；这是整轮音频修改的总数。

本轮建立的是时钟处理规则与自动验证。设备异常现场、长时漂移和真实语音质量仍需要对应录音，不能把 estimated 时间写成已验证的真实设备时间。

## 可以复用的经验

数据完整性和时间可信度需要分别表达。先保留可用数据，再标注时间估算，比遇到时间错误就丢数据更便于恢复与排查；但估算信息必须沿链路保留，不能在归档时悄悄变成“精确时间”。
