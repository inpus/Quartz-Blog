# 双路语音实时识别积压与丢块

## 涉及文件

| 文件 | 作用 |
| --- | --- |
| `server/libs/slowlane/voice_chain/voice_chain.cpp`、`voice_chain.hpp` | PCM 处理、分源状态、ASR 调度与排尾 |
| `server/libs/slowlane/voice_chain/source_queue.hpp` | 按来源限制容量、轮询取出与停止控制保序 |
| `server/libs/slowlane/voice_chain/cuda_dpdfnet.cpp`、`cuda_dpdfnet.hpp` | DPDFNet8 的 CUDA Graph 推理 |
| `server/libs/slowlane/voice_chain/denoiser.cpp` | 去噪后端接入 |
| `config/voice.webrtc.yaml` | 去噪后端和 GPU 配置 |
| `server/tests/voice_queue_tests.cpp` | 来源隔离、公平性与停止排空测试 |

## 背景与现象（S）

语音链路为 DPDFNet8 去噪 → Silero VAD → Qwen3-ASR。早期 90.2 秒真实旧录音完整处理约需 119 秒，单独去噪 RTF 约 1.24。RTF 是处理耗时与音频时长之比，大于 1 意味着处理速度跟不上实时输入。

接入 CS2、Oopz 双路 WebRTC 音频后，同步语音处理会积压并丢块。传输收到完整音频，不代表模型来得及消费。

## 要达到的目标（T）

在有界内存下处理双路实时输入，保持每源独立状态；ASR 耗时不阻塞前级 PCM，停止时可以排尾并核对样本数，而不是通过扩大队列隐藏延迟。

## 排查与根因（A）

问题有两个相互叠加的部分：

1. **同步流水线阻塞。** P1 如果直接执行去噪、VAD 和 ASR，某段识别期间就不能及时处理后续 PCM；一个来源也会影响另一个来源。
2. **去噪吞吐本身不足。** 即使把工作搬到后台，RTF 持续大于 1，队列还是会增长。线程解耦解决调度，不能凭空消除计算瓶颈。

因此先按输入样本、排队时间、每阶段耗时和丢弃计数拆开观察，再分别修改调度与模型执行。

## 如何解决

### 拆分 PCM 与 ASR

P1 只投递不可变 PCM。后台工作线程按来源轮询，每次处理 100ms 块，各来源维护独立去噪/VAD 状态；分段交给另一条有界 ASR 工作队列。

PCM 每源最多 4 个普通块，ASR 每源最多 2 个普通分段。来源容量互相隔离，缺少 Oopz 输入时不会等待它凑包，停止控制按源保序。满队列仍显式计数。

```text
接入/P1 → 分源 PCM 队列 → 去噪/VAD → 分源 ASR 队列 → 转写
                            CS2 去噪
                            Oopz 直接 VAD
```

这是共享 PCM 工作线程与独立 ASR 阶段的流水线，不是两套 ASR 同时推理。

### 优化 DPDFNet8

CS2 使用 ORT I/O Binding、固定 GPU 缓冲和 CUDA Graph。谱与循环状态绑定固定地址，循环状态在两份显存缓冲中交替；FFT/IFFT 仍由 CPU OpenCV 完成。Oopz 独立通话音频直接进入 VAD，避免额外去噪。

Graph 在实际处理线程上捕获并预热，服务开放前完成；停止或时间断点只重置状态、复用权重，不每 100ms 重新加载模型。候选配置明确指定 `ort_cuda_graph` 与 GPU1，并禁止去噪静默回退 CPU。

### 分开表达停止与完成

先停止媒体并排尾，再排空 PCM/ASR 队列。`stopped` 可以同时报告转写 pending；真正结束后写 `voice-summary.json` 并发出 transcription_complete，避免把“已经停采”误读成“文字已经全部生成”。

## 验证与结果（R）

2026-10-26 暖机后同源 10 秒对照：

| 指标 | 原 sherpa 后端 | CUDA Graph 后端 |
| --- | ---: | ---: |
| 处理时间 | 12.651 秒 | 4.537 秒 |
| RTF | 1.265 | 0.454 |
| 输入/输出样本 | 160000/160000 | 160000/160000 |

两后端输出最大绝对差约 `9.59e-5`，SNR 约 72.95dB，用于检查数值一致性。

70 秒跨机回放会话 `20261026-030416-h2gc` 每源有效音频为 68.38 秒：

| 指标 | CS2 | Oopz |
| --- | ---: | ---: |
| 有效输入/处理样本 | 1094080/1094080 | 1094080/1094080 |
| VAD 分段/转写 | 3/3 | 22/22 |
| PCM、ASR 队列丢弃 | 0 | 0 |
| 处理错误、重复、时间断点 | 0 | 0 |

服务器已有 `final-acceptance.json` 与以上计数一致。输入来自既有真实录音文件回放和固定截图，证明该输入下跨机实时处理完整；它没有验收真实 WASAPI 设备现场、长期稳定性或转写准确率。

## 可以复用的经验

实时流水线要同时满足阶段吞吐和调度隔离。队列容量决定可承受的短时波动，RTF 决定能否长期跟上。最终用输入、处理、丢弃和输出计数闭合，才能区分真正追上与静默丢弃。
