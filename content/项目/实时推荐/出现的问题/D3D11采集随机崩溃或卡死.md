# D3D11 采集随机崩溃或卡死

## 涉及文件

- `client/src/capture_video.cpp`：D3D11 初始化、WGC 回调、纹理复制和读取。
- `client/src/capture_video.hpp`：采集对象生命周期。

## 问题

采集时出现随机崩溃和线程卡死，每次出错的位置还不完全一样，有时表现得像堆损坏。图像内容没有固定规律，很难靠某一帧复现。

## 定位

我先检查了纹理复制和读取使用的对象，再看这些调用运行在哪个线程。

采集使用 `Direct3D11CaptureFramePool::CreateFreeThreaded`，FrameArrived 由 WinRT 线程池触发。设备和 immediate context 在采集初始化处创建，回调里又使用同一个 context 做 `CopyResource()`、`Map()`、`Unmap()`。这里不能因为代码只有一个采集对象，就认为所有底层调用天然串行。

这次缺少的是 D3D11 context 的多线程保护。与 `ID3D11Device` 的一般线程安全性不同，不能直接假设共享 immediate context 的调用也可以不做协调。

## 修改前

下面省略错误处理，只保留当时的资源使用关系：

```cpp
winrt::com_ptr<ID3D11Device> device;
winrt::com_ptr<ID3D11DeviceContext> context;
D3D11CreateDevice(/* 参数省略，输出 device 和 context */);

// 没有设置 context 的多线程保护，就启动 WGC。
frame_pool.FrameArrived([context, staging](auto const& sender, auto&&) {
    if (auto frame = sender.TryGetNextFrame()) {
        // 从 frame.Surface() 取得 texture。
        context->CopyResource(staging.get(), texture.get());
        context->Map(staging.get(), 0, D3D11_MAP_READ, 0, &mapped);
        // 读取像素。
        context->Unmap(staging.get(), 0);
    }
});
```

这个片段只说明故障路径，`texture`、`mapped` 等局部准备代码没有展开。问题在于同一个 immediate context 被跨线程使用时，没有建立对应的访问保护。

## 修改后

在初始化完成、开始采集之前，通过 context 获取 `ID3D11Multithread` 并打开保护。当前代码为：

```cpp
winrt::com_ptr<ID3D11Device> device;
winrt::com_ptr<ID3D11DeviceContext> context;
HRESULT hr = D3D11CreateDevice(
    nullptr, D3D_DRIVER_TYPE_HARDWARE, nullptr, 0,
    nullptr, 0, D3D11_SDK_VERSION,
    device.put(), nullptr, context.put());
if (FAILED(hr)) {
    return;
}

// 需要 d3d11_4.h。
auto multithread = context.as<ID3D11Multithread>();
multithread->SetMultithreadProtected(TRUE);

// 完成后再创建帧池、注册回调并启动采集。
```

同一段初始化还要把 D3D11 设备包装为 WGC 需要的 WinRT 设备：

```cpp
auto dxgi_device = device.as<IDXGIDevice>();
winrt::com_ptr<::IInspectable> inspectable;
winrt::check_hresult(CreateDirect3D11DeviceFromDXGIDevice(
    dxgi_device.get(), inspectable.put()));
auto d3d_winrt = inspectable.as<d3dx11::IDirect3DDevice>();
```

这两步不能混为一谈：包装解决 D3D11/DXGI 到 WinRT 的接口转换；多线程保护解决 context 共享访问。直接把普通 D3D11 device 当成 WinRT device 做接口转换，之前也出现过 `E_NOINTERFACE`。

## 为什么这样改

开启 `ID3D11Multithread` 保护后，相关 D3D11 调用有了运行时提供的同步机制，避免共享 context 因缺少并发保护而发生异常。

这里没有给整个回调加一把大锁，因为我需要保护的是 D3D11 context 访问，而不是让纹理读取、编码、入队全部互相等待。保护必须在回调运行前设好，否则先启动采集再补设置，仍然留下未保护的时间窗口。

它也不替代采集对象的生命周期管理。关闭帧池、停止回调、释放纹理和销毁 context 仍需要各自按正确顺序完成。

## 验证

2026-10-04 记录中，这项问题修复后完成了 15 秒真机采集、上传和归档。原记录没有单独的长时间压力测试数据，因此这里保留该次验证范围。

## 总结

我没有继续围着随机崩溃的位置猜，而是把共享的 device/context 和使用它们的线程列出来，最后定位到 immediate context 缺少多线程保护。图形采集里，设备能创建成功、接口能调用，并不代表跨线程使用方式正确。
