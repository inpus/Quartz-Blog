# 音频降采样后出现混叠失真

## 涉及文件

- `client/src/resampler.cpp`、`resampler.hpp`：下混、流式 FIR 和输出量化。
- `client/src/capture_audio.cpp`：WASAPI 输入和重采样器调用。
- `client/src/raw_audio_recorder.cpp`：原生音频及同源对照录音。

## 问题

WASAPI 输入为 48kHz，语音模型需要 16kHz。我原来每 3 个采样点取平均，虽然输出数量对了，但高频没有被充分滤掉，会折叠到语音频段，影响声音质量。

真实录音转写不好时，我先把采样率转换单独拿出来验证，没有直接把原因归给 ASR。

## 修改前

`dc35b6c` 之前的 resampler 对每个声道这样处理，省略最后的声道平均和 S16 限幅：

```cpp
const std::size_t total_frames = interleaved.size() / channels;
const std::size_t out_frames = total_frames / 3;
for (std::size_t g = 0; g < out_frames; ++g) {
    double mix = 0;
    for (int c = 0; c < channels; ++c) {
        const float* base = interleaved.data() + (g * 3) * channels + c;
        double group = (static_cast<double>(base[0]) + base[channels] +
                        base[2 * static_cast<std::size_t>(channels)]) / 3.0;
        mix += group;
    }
    // mix /= channels，再量化写入 out。
}
```

三个点平均相当于一个很短的 FIR，滤波能力不足；`total_frames / 3` 还把当前调用末尾不足 3 帧的数据直接舍掉，不适合任意长度的流式分包。

16kHz 的 Nyquist 频率为 8kHz。48kHz 输入中的 10kHz、12kHz 分量，如果抽取前没有压低，会分别折叠到 6kHz、4kHz，落进有效语音带宽。

## 修改后

我改成带状态的 `Mono16kResampler`。构造时生成 Kaiser 窗 sinc 滤波核，push 时保存历史输入，只有足够计算的输出点才交付。

### 先准备滤波核

下面是当前参数计算与权重生成的关键部分：

```cpp
divisor_ = std::gcd(rate, output_rate);   // output_rate = 16000
half_ = static_cast<int>(std::ceil(
    48.0 * std::max(1.0, double(rate) / output_rate)));
const int phases = output_rate / divisor_;
const double cutoff = 0.45 * std::min(rate, output_rate) / rate;
constexpr double beta = 8.6;

// 在每个相位中，为 tap=-half_ 到 +half_ 生成系数。
const double y = 2 * cutoff * x;
const double sinc = std::abs(y) < 1e-14 ? 1 :
    std::sin(std::numbers::pi * y) / (std::numbers::pi * y);
const double weight = 2 * cutoff * sinc * window;
// 每个相位生成完成后，所有系数除以该相位的 total。
```

48k→16k 时 `half_=144`，共 289 taps；截止设计值是 7.2kHz。给 8kHz 边界留出过渡带，比直接把截止设到边界更适合有限长度滤波器。系数归一化使直流增益约为 1。

### 用整数关系定位输出采样点

下面摘取 `emit()` 的主循环：

```cpp
const int64_t count = input_frames_ * output_rate / rate_;
while (emitted_ < count) {
    const int64_t numerator = emitted_ * rate_;
    const int64_t center = numerator / output_rate;
    if (!final && center + half_ >= input_frames_) break;

    const auto& kernel = kernels_[(numerator % output_rate) / divisor_];
    double value = 0;
    const int64_t first = std::max<int64_t>(0, center - half_);
    const int64_t last = std::min<int64_t>(input_frames_ - 1, center + half_);
    for (int64_t frame = first; frame <= last; ++frame) {
        value += buffer_[static_cast<std::size_t>(frame - buffer_start_)] *
                 kernel[frame - center + half_];
    }
    out.push_back(quantize(value));
    ++emitted_;
}
```

`input_frames_` 和 `emitted_` 跨 push 累计。第 k 个输出点对应输入位置 `k × rate / 16000`，整数部分选中心，小数部分选相位，避免不断累加浮点步长引起位置漂移。44.1kHz 等非整数倍采样率也能按同一套关系处理。

停止时调用 flush，让最后不足前视长度的输出也完成：

```cpp
std::vector<int16_t> Mono16kResampler::flush() {
    if (finished_) return {};
    finished_ = true;
    return rate_ == output_rate ? std::vector<int16_t>{} : emit(true);
}
```

## 为什么这样改

FIR 在抽取前充分抑制带外高频，避免高频折叠成新的语音带内分量；跨包状态保证相同输入无论怎么分包都按同一时间轴计算。

正常 push 要等中心右侧 144 个输入点，48kHz 下约 3ms。它增加的是交付延迟，不是把音频内容的时间戳改成处理完成时间。最终输出数量仍按 `floor(总输入帧数 × 16000 / 输入采样率)` 控制。

为了区分滤波与其他环节，我另外保存原生录音，以及从同一份下混 S16 生成的 48k/16k 对照，不混入去噪或增益调整。

## 验证

2026-10-17 的固定正弦探针结果：

| 输入 | 旧实现 | FIR 实现 |
| --- | --- | --- |
| 1kHz 通带增益 | 约 −0.05dB | 约 −0.00016dB |
| 10kHz 折叠到 6kHz | 约 −5.92dB | 通过低于 −70dB 门限 |
| 12kHz 折叠到 4kHz | 约 −9.54dB | 通过低于 −70dB 门限 |

另测了 44.1/48/96kHz 输入、不同分包、输出长度、尾部、脉冲时刻和立体声抵消。报告中的部分 −300dB 是 S16 量化为零后的计算下限。该轮验证了重采样缺陷修复，没有用它替代新真实语音的 ASR 准确率验证。

## 总结

我把简单的三点平均改成流式有理相位 FIR，解决了抗混叠不足和分包边界处理问题。降采样不是每隔几个点取一个，必须先限制输入带宽；实现上还要保留跨包状态、稳定定位输出点，并在停止时把尾部处理完。
