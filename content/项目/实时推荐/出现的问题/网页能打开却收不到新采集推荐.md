# 网页能打开却收不到新采集推荐

## 涉及文件

| 文件 | 作用 |
| --- | --- |
| `panel/connection.js` | 读取实际 WS 端口并构造连接 URL |
| `panel/panel.js` | 副屏连接初始化 |
| `server/apps/server_main.cpp` | HTTP 运行配置接口与实际服务装配 |
| `config/server.webrtc.yaml` | WebRTC 候选实例端口配置 |
| `tools/test_panel_connection.mjs` | 端口、HTTPS、IPv6 与非法配置测试 |

## 背景与现象（S）

WebRTC 候选实例独立使用 HTTP8003、WS9003，原实例为 HTTP8000、WS9000。用户打开 8003 页面后，网页能加载，客户端也向 9003 发送媒体，但副屏收不到新采集观测，无法触发推荐。

## 要达到的目标（T）

网页连接到提供该页面的应用实例对应的 WebSocket 服务，支持多实例配置，同时为代理环境保留显式覆盖入口。

## 排查与根因（A）

页面原来固定连接 9000。8003 的静态资源属于新实例，实时订阅却进入旧实例，形成：

```text
采集端 → 9003 新实例 → 新观测
浏览器 → 8003 加载页面 → 固定连接 9000 旧实例
```

两个实例都健康也无法解决这种接线错误。HTTP 成功只证明资源可取，WebSocket 握手成功也只证明某个实例可连，二者都不能证明业务会话一致。

## 如何解决

服务端新增 `GET /api/runtime`，返回当前进程实际 `websocket_port`。前端从提供页面的 HTTP 服务读取该值，并根据页面 URL 构造 `/ws/panel` 地址：

```javascript
const url = new URL(location.href);
url.protocol = location.protocol === "https:" ? "wss:" : "ws:";
url.port = String(runtime.websocket_port);
url.pathname = "/ws/panel";
url.search = "";
url.hash = "";
```

端口先检查是否为 1–65535 的整数。使用 URL API 保留 IPv6 主机等格式，HTTPS 页面选择 wss。反向代理可通过显式 `?ws=` 覆盖，并校验协议。

运行配置请求失败时显示错误并重试，不猜另一个服务端口，避免悄悄连到错误实例。

## 验证与结果（R）

2026-10-26 在 8003 副屏联调中，真实编码上传参考截图经 OCR 识别“短梯”，SQLite 自动匹配视频 1、2、9、19。四个 video 均为 `paused=false`、`readyState=4`、`error=null`，分辨率 1920×1080，播放时间持续推进。

连接专项测试覆盖实际端口、HTTPS、IPv6、显式代理 URL 和非法运行配置，并包含在当轮 25 项前端回归中。停止采集后清空，新会话恢复推荐。

这组结果来自候选实例的历史验收，不表示整理当天这些端口仍在运行。

## 可以复用的经验

多实例系统应从当前服务的真实配置发现关联地址。排查“页面可用但没有数据”时，要把静态页面、实时订阅、查询 API 和采集会话画在同一张连接关系中，核对它们是否属于同一实例。
