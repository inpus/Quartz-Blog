# 敌人云雾刚出现就扩散到未来 10 秒

## 涉及文件

| 文件 | 作用 |
| --- | --- |
| `panel/fog-clock.js` | 区分当前显示时刻与显式未来预览 |
| `panel/enemy-fog.js` | 目标关联、证据年龄与云雾演化 |
| `panel/radar-replay.js` | 回放时钟和云雾计算接线 |
| `panel/radar-replay.html`、`radar-replay.css` | 渐进播放、预览开关和状态提示 |
| `tools/test_enemy_fog.mjs`、`test_fog_clock.mjs` | 扩散、关联范围和旧链接行为回归 |

## 背景与现象（S）

2026-10-28 的离线雷达回放中，一个刚刚观测到的敌人，云雾立刻铺开到很大范围，看起来不像随时间渐进扩散。逐样本播放又会跳过约 2 秒采集间隔，进一步放大突跳感。

## 要达到的目标（T）

默认显示敌人在当前时刻的可能位置：新鲜观测从小范围开始，经过多少时间就扩散相应距离。未来预测单独作为用户显式开启的预览，不混入当前状态或当前目标关联。

## 排查与根因（A）

旧版将未来预测窗口直接加到显示时刻：

```javascript
fieldAt(playhead + forecast, playhead)
```

默认 `forecast=10`，所以年龄为 0 的新观测一开始就按未来 10 秒计算。目标关联也使用多加 10 秒的可达范围，可能将当前尚不可达的新观测错误合并到已有目标。

这不是简单的透明度或扩散速度参数问题，而是时间语义错误：未来窗口被当作已经经过的时间。

## 如何解决

默认改为 `fieldAt(playhead, playhead)`。新观测将本目标证据年龄归零，其他临时 ID 继续按各自年龄演化。

`fog-clock.js` 将预览开关与预览秒数分开：

```javascript
export function fogDisplayTime(captureTime, clock) {
  return captureTime + (clock.preview ? clock.seconds : 0);
}
```

旧链接即使带 `forecast=10`，未显式 `preview=1` 仍显示当前时刻；页面也需要手动开启预览才展示未来偏移控件。

同时完成三处配套修正：默认按真实采集时间渐进播放；当前关联范围使用 `60 + 扩散速度 × 已过时间`，不额外加未来 10 秒；暂停时回放时钟与云雾一起停止。历史问号 `enemy_q` 仍保留其初始 2 秒陈旧语义，Demo 只作对照输入。

## 验证与结果（R）

2026-10-28 云雾、地图和时钟相关测试 22/22 通过。全 502 帧检查中，默认链接和旧 forecast 链接显示偏移均为 0，无导航格点外密度泄漏，移除 Demo 参考不改变结果。

第 26 样本 E02 使用相同输入，只推进经过时间：

| 已经过时间 | 非零支持格点数 |
| --- | ---: |
| 0 秒 | 11 |
| 0.25 秒 | 24 |
| 0.75 秒 | 110 |
| 1.5 秒 | 472 |

服务器保存的 `check-progressive.json` 与该表一致。浏览器也验证了旧链接默认当前时刻、手动预览切换、播放渐进与暂停停止。

## 可以复用的经验

预测系统需要明确三个时间：证据发生时间、当前评估时间、未来预览时间。预测窗口不应自动增加证据年龄；同一时间约束还必须用于目标关联，否则画面修正了，内部状态仍可能错误合并。
