# 敌人云雾刚出现就扩散到未来 10 秒

## 涉及文件

- `panel/fog-clock.js`：当前时刻与未来预览。
- `panel/enemy-fog.js`：证据年龄、扩散和目标关联。
- `panel/radar-replay.js`：回放时间与云雾接线。
- `panel/radar-replay.html`、`radar-replay.css`：渐进播放与预览控件。
- `tools/test_enemy_fog.mjs`、`test_fog_clock.mjs`：扩散、关联和链接参数回归。

## 问题

刚观测到的敌人，云雾立即覆盖很大范围；播放时还会突然跳大。我检查时间参数后发现，默认把未来 10 秒预测窗口加到了当前显示时刻，相当于目标一出现就被当作已经过去了 10 秒。

逐样本播放还会一次跳过约 2 秒采集间隔，使扩散突跳更明显。

## 修改前

旧调用为：

```javascript
const field = fog.fieldAt(playhead + forecast, playhead);
// forecast 默认是 10。
```

`fieldAt(time, observedUntil)` 的第一个参数决定显示哪个时刻的分布，第二个参数限制最多使用到哪个时刻的观测。第二个参数没有消除第一个参数中的未来偏移。

当 `playhead=100`、目标 `seen=100` 时，传入显示时间 110：

```text
age = 110 - 100 = 10 秒
radius = seedRadius + speed × 10
```

以上数值是参数示例。旧目标关联还把未来窗口算进可达范围，可能把当前还走不到的新观测并入旧 ID。

## 修改后

### 默认显示现在，未来必须显式开启

`fog-clock.js` 把开关和秒数分开：

```javascript
export function initialFogClock(search = "") {
  const params = new URLSearchParams(search);
  const requested = Number(params.get("forecast"));
  return {
    preview: params.get("preview") === "1",
    seconds: params.has("forecast") && Number.isFinite(requested)
      ? Math.max(0, Math.min(10, requested)) : 3
  };
}

export function fogDisplayTime(captureTime, clock) {
  return captureTime + (clock.preview ? clock.seconds : 0);
}
```

接线可写成下面的等价形式：

```javascript
const displayTime = fogDisplayTime(playhead, clock);
const field = fog.fieldAt(displayTime, playhead);
```

不开预览就是 `fieldAt(playhead, playhead)`。旧链接单独带 `forecast=10` 也不会进入未来，必须带 `preview=1` 或由页面手动开启。

### 扩散按显示时间，观测按截止时间

当前 `fieldAt()` 的时间计算为：

```javascript
const cutoff = Math.min(time, observedUntil);
const tracks = this.hypothesesAt(cutoff);
for (const track of tracks) {
  const age = Math.max(0, time - track.seen);
  const evidenceAge = Math.max(0, cutoff - track.seen);
  const speed = this.spreadSpeed(track);
  const radius = seedRadius + speed * age;
  const sigma = seedRadius * .6 + speed * age * .38;
  // 沿导航图距离计算支持格点及权重。
}
```

正常显示时 age 与 evidenceAge 一致；预览时允许分布向未来扩散，但只能消费截止到 playhead 的观测，不能用未来检测结果补答案。新鲜目标被直接观测更新后，seen 随之更新，本目标重新收拢，其他 ID 继续按自己的年龄演化。

历史问号 `enemy_q` 另有初始 2 秒陈旧量，所以不能把它也解释为年龄为 0 的直接观测。

### 当前目标关联只用已过时间

`candidate()` 的关键判断为：

```javascript
const elapsed = Math.max(0, event.time - track.seen);
const speed = this.spreadSpeed(track);
const gate = this.settings.seedRadius + speed * elapsed;

if (Math.hypot(event.xy[0] - track.origin.xy[0],
               event.xy[1] - track.origin.xy[1]) > gate) return null;
const distances = this.graph.distances(track.origin);
const distance = Math.min(...event.origin.anchors.map(
  a => distances[a.node] + a.distance));
if (distance > gate) return null;
```

先用直线距离快速排除，再用导航图路径距离检查，避免隔墙很近就匹配。gate 不加未来窗口；页面开启预览也不能改变当前 ID 关联结果。

## 为什么这样改

之前混用了“已经过去多久”和“想预测多远”。我把这两个量分开：默认用经过时间演化，显式预览只改变显示时刻；观测截止和关联仍受当前时间限制。

回放也改为按采集时间渐进推进，而不是默认逐样本跳转。暂停时 playhead 不动，云雾自然停止；回看则按选中时刻重建。

## 验证

2026-10-28，相关测试 22/22 通过。502 帧检查中，默认和旧 forecast 链接的显示偏移均为 0，没有导航格点外密度泄漏，移除 Demo 参考不影响输出。

浏览器验证了渐进播放、暂停与预览切换。记录为 `var/progressive-fog-20261028/check-progressive.json`。

## 总结

我修的是时间参数的含义，不是简单调小扩散速度。显示时间、观测截止时间和未来窗口要分别处理，目标关联也必须使用当前可达范围，否则画面看起来正常了，内部仍可能把两个目标合错。
